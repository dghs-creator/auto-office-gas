    Chapter 09: 담당자 자동 알림 ① – 이메일로 집계 결과 보내기¶

    Part 3: 알림·소통 자동화 – 필요한 사람에게 정확히 전달하기

    🎯 이 장에서 배우는 것¶

    • MailApp.sendEmail 메서드를 사용하여 이메일을 자동 발송할 수 있다
    • 스프레드시트 데이터를 읽어와 이메일 본문에 포함하여 보낼 수 있다
    • HTML 형식의 이메일 본문 템플릿을 작성할 수 있다
    • GAS 이메일 일일 발송 한도와 제한사항을 이해하고 대응할 수 있다

    💡 왜 이걸 배우나요?¶

    상황을 상상해 보세요.

    매주 금요일 오후, 김 대리는 한숨을 쉽니다. 이번 주 프로젝트별 진행 현황을 집계한 스프레드시트를 열어놓고, 팀장님과 관련 부서 담당자 5명에게 각각 이메일을 작성해야 합니다. 스프레드시트 데이터를 복사하고, 이메일 본문에 붙여넣고, 인사말을 쓰고, 받는 사람을 하나하나 입력합니다. 매번 같은 패턴인데, 30분이 훌쩍 지나갑니다. 실수로 지난 주 데이터를 보낸 적도 있습니다.

    이 작업을 버튼 하나로 끝낼 수 있다면?

    Google Apps Script의 MailApp.sendEmail을 사용하면, 스프레드시트에서 데이터를 자동으로 읽어 → 보기 좋은 이메일 본문을 만들고 → 지정된 담당자에게 발송하는 것까지 한 번의 클릭으로 처리할 수 있습니다.

    이 장을 마치면 여러분은 다음과 같은 업무를 자동화할 수 있습니다.

    • 📊 주간 매출 집계 보고 → 팀장에게 자동 메일 발송
    • 🚌 프로젝트 일정 확정 알림 → 관련 부서 담당자에게 발송
    • 📋 일일 업무 현황 보고 → 매일 아침 자동 요약 메일

    📚 핵심 개념¶

    개념 1: MailApp – GAS의 우체부 📮¶

    비유로 시작합시다.

    회사에 전담 메신저가 한 명 있다고 상상해 보세요. 여러분이 "이 내용을 김 팀장님 이메일로 보내줘"라고 말하면, 그 메신저가 편지를 작성하고, 봉투에 주소를 쓰고, 우체통에 넣는 것까지 대신 해줍니다. MailApp이 바로 그 메신저입니다.

    정확한 정의

    MailApp은 Google Apps Script에 내장된 이메일 발송 서비스입니다. Gmail 계정을 통해 이메일을 보내는 기능을 코드로 제어할 수 있게 해줍니다.

    가장 기본적인 사용법

    MailApp.sendEmail("receiver@company.com", "메일 제목", "메일 본문 내용");

    이 한 줄이면 이메일이 발송됩니다. 세 개의 정보만 전달하면 됩니다.

    • 첫 번째: 받는 사람 이메일 주소
    • 두 번째: 메일 제목
    • 세 번째: 메일 본문

    예시로 확인

    function sendSimpleEmail() {
  MailApp.sendEmail(
    "teamlead@company.com",
    "7월 셋째주 프로젝트 현황 보고",
    "안녕하세요, 금주 프로젝트 현황을 보고드립니다.\n\n프로젝트A: 진행률 85%\n프로젝트B: 진행률 60%"
  );
}

    실무 TIP 💼 \n은 줄바꿈을 의미합니다. 이메일 본문에서 문단을 나눌 때 사용하세요. \n\n처럼 두 번 쓰면 빈 줄이 하나 생깁니다.

    개념 2: 객체 파라미터 – 더 정교한 이메일 보내기 🎛️¶

    비유로 시작합시다.

    기본 sendEmail이 "편지를 보내줘"라면, 객체 파라미터 방식은 택배 송장을 꼼꼼히 작성하는 것과 같습니다. 받는 사람, 참조자, 숨은참조, HTML 본문, 첨부파일까지 세밀하게 지정할 수 있습니다.

    정확한 정의

    sendEmail에 하나의 객체(중괄호 {})를 전달하면, 다양한 옵션을 키-값 쌍으로 설정할 수 있습니다. 이를 "객체 파라미터 방식"이라고 합니다.

    사용 가능한 주요 옵션들

    • to: 받는 사람 이메일 (필수)
    • subject: 메일 제목 (필수)
    • body: 일반 텍스트 본문
    • htmlBody: HTML 형식 본문 (body보다 우선 적용)
    • cc: 참조 (Carbon Copy)
    • bcc: 숨은참조 (Blind Carbon Copy)
    • name: 발신자 표시 이름
    • replyTo: 회신 받을 이메일 주소

    예시로 확인

    function sendDetailedEmail() {
  MailApp.sendEmail({
    to: "teamlead@company.com",
    cc: "manager@company.com",
    subject: "7월 셋째주 프로젝트 현황 보고",
    htmlBody: "<h2>프로젝트 현황</h2><p>상세 내용은 아래와 같습니다.</p>",
    name: "업무자동화 시스템"
  });
}

    실무 TIP 💼 htmlBody를 사용하면 굵은 글씨, 표, 색상 등으로 보기 좋은 이메일을 만들 수 있습니다. 일반 body만 사용하면 텍스트만 표시됩니다. 두 가지를 모두 넣으면 htmlBody가 우선 표시되고, HTML을 지원하지 않는 환경에서 body가 대체 텍스트로 사용됩니다.

    개념 3: 스프레드시트 데이터 → 이메일 본문 조립 🧩¶

    비유로 시작합시다.

    보고서 작성을 떠올려 보세요. 엑셀에서 숫자를 확인하고 → 워드에 옮겨 적고 → 문장으로 다듬는 과정. 이 "확인 → 옮기기 → 다듬기"를 코드가 자동으로 해주는 것입니다.

    정확한 정의

    SpreadsheetApp으로 시트의 데이터를 읽어온 뒤, 문자열 조합(템플릿 리터럴)을 사용해 이메일 본문을 동적으로 생성하는 패턴입니다.

    핵심 흐름

    flowchart LR A["📊 스프레드시트\n데이터 읽기"] --> B["🔧 본문 텍스트\n조립하기"] B --> C["📧 이메일\n발송하기"]

    예시로 확인 – 템플릿 리터럴 활용

    function buildEmailBody() {
  // 1단계: 데이터 읽기
  var projectName = "웹사이트 리뉴얼";
  var progress = 85;
  var deadline = "2024-08-15";

  // 2단계: 본문 조립 (백틱 ` 사용)
  var body = `
    프로젝트명: ${projectName}
    진행률: ${progress}%
    마감일: ${deadline}

    현재 순조롭게 진행 중입니다.
  `;

  Logger.log(body);  // 결과 확인
}

    주의사항 ⚠️ 템플릿 리터럴은 작은따옴표(')나 큰따옴표(")가 아니라 백틱(`)으로 감쌉니다. 키보드에서 숫자 1 왼쪽, 물결표(~) 아래에 있는 키입니다. ${ } 안에 변수를 넣으면 자동으로 값이 들어갑니다.

    개념 4: GAS 이메일 발송 한도 – 무제한이 아닙니다! 🚧¶

    비유로 시작합시다.

    아무리 부지런한 메신저라도 하루에 배달할 수 있는 편지 수에는 한계가 있습니다. Google도 스팸 방지와 서버 보호를 위해 하루에 보낼 수 있는 이메일 수를 제한합니다.

    정확한 정의

    Google Apps Script의 MailApp은 Google 계정 유형에 따라 일일 이메일 발송 한도(Daily Quota)가 다릅니다.

    • 무료 Gmail 계정 (@gmail.com): 하루 약 100통
    • Google Workspace 계정 (회사/조직 계정): 하루 약 1,500통

    주의사항 ⚠️ 이 한도는 수신자 수 기준입니다. 한 통의 이메일에 받는 사람 10명을 넣으면 10통으로 카운트됩니다. CC, BCC에 포함된 주소도 모두 카운트됩니다.

    남은 발송 가능 횟수 확인 방법

    function checkEmailQuota() {
  var remaining = MailApp.getRemainingDailyQuota();
  Logger.log("오늘 남은 발송 가능 횟수: " + remaining + "통");
}

    한도 초과 시 대응 전략

    • 발송 시점 분산: 모든 메일을 한꺼번에 보내지 말고, 시간대를 나눠서 발송
    • 수신자 그룹 활용: 개별 발송 대신 그룹 이메일 주소 활용
    • 발송 전 잔여 횟수 확인: 코드 시작 부분에서 getRemainingDailyQuota() 체크

    function readProjectData() {
  // 현재 스프레드시트의 '프로젝트현황' 시트 가져오기
  var ss = SpreadsheetApp.getActiveSpreadsheet();

  var lastRow = sheet.getLastRow();
  var dataRange = sheet.getRange(2, 1, lastRow - 1, 5);  // 2행~마지막행, A~E열
  var data = dataRange.getValues();

  // 읽어온 데이터 확인
  for (var i = 0; i < data.length; i++) {
    var projectName = data[i][0];  // A열: 프로젝트명
    var manager = data[i][1];       // B열: 담당자
    var progress = data[i][2];      // C열: 진행률
    var status = data[i][3];        // D열: 상태
    var note = data[i][4];          // E열: 비고

    Logger.log(projectName + " | " + manager + " | " + progress + "% | " + status);
  }
}

// 상태별 색상 반환 함수
function getStatusColor(status) {
  switch(status) {
    case "정상": return "#34a853";   // 초록
    case "완료": return "#1a73e8";   // 파랑
    case "지연": return "#d93025";   // 빨강
    case "주의": return "#f9ab00";   // 노랑
    default: return "#999999";       // 회색
  }
}

/**
 * 상태별 배지 색상 반환
 * @param {string} status - 상태 텍스트
 * @return {string} 색상 코드
 */
function getStatusColor(status) {
  switch(status) {
    case "정상": return "#34a853";
    case "완료": return "#1a73e8";
    case "지연": return "#d93025";
    case "주의": return "#f9ab00";
    default: return "#999999";
  }
}


/**

  if (remaining > 50) {

  }
}

    ⚠️ 자주 하는 실수¶

    실수 1: 이메일 주소에 공백이나 오타가 있는 경우¶

    // ❌ 이렇게 하면 에러!
MailApp.sendEmail(" teamlead@company.com ", "제목", "내용");
//                 ^ 앞뒤에 공백

// ✅ trim()으로 공백 제거!
var email = settingSheet.getRange("B1").getValue().toString().trim();
MailApp.sendEmail(email, "제목", "내용");

    스프레드시트에서 이메일을 읽어올 때 앞뒤 공백이 숨어 있을 수 있습니다. trim()을 습관적으로 사용하세요.

    실수 2: htmlBody와 body를 혼동하는 경우¶

    // ❌ body에 HTML을 넣으면 태그가 그대로 보임!
MailApp.sendEmail({
  to: "receiver@company.com",
  subject: "보고서",
  body: "<h1>제목</h1><p>내용</p>"  // 태그가 텍스트로 표시됨
});

// ✅ HTML은 반드시 htmlBody에!
MailApp.sendEmail({
  to: "receiver@company.com",
  subject: "보고서",
  htmlBody: "<h1>제목</h1><p>내용</p>"  // HTML로 렌더링됨
});

    body는 순수 텍스트용이고, htmlBody가 HTML 렌더링용입니다. HTML 태그를 사용하려면 반드시 htmlBody를 사용해야 합니다.

    실수 3: 시트 이름이 다른 경우 (null 에러)¶

    // ❌ 시트 이름이 정확히 일치하지 않으면 null 반환
var sheet = ss.getSheetByName("프로젝트 현황");  // 공백이 다르거나 오타
// sheet.getRange(...)  → TypeError: Cannot read property 'getRange' of null

// ✅ 시트 이름을 정확히 확인하거나, null 체크 추가
var sheet = ss.getSheetByName("프로젝트현황");
if (sheet === null) {
  Logger.log("⚠️ '프로젝트현황' 시트를 찾을 수 없습니다. 시트 이름을 확인하세요.");
  return;
}

    getSheetByName()은 시트를 찾지 못하면 null을 반환합니다. 이후 코드에서 null.getRange()를 호출하면 에러가 발생합니다. 시트 이름의 공백, 대소문자까지 정확히 일치해야 합니다.

    실수 4: 일일 발송 한도 초과¶

    // ❌ 한도 확인 없이 대량 발송하면 중간에 에러!
for (var i = 0; i < 200; i++) {
  MailApp.sendEmail(emailList[i], "제목", "내용");  // 100번째에서 멈출 수 있음
}

// ✅ 발송 전 한도를 확인하고, 루프 안에서도 체크
var quota = MailApp.getRemainingDailyQuota();
var sendCount = Math.min(emailList.length, quota - 5);  // 5통 여유 확보

for (var i = 0; i < sendCount; i++) {
  MailApp.sendEmail(emailList[i], "제목", "내용");
}
Logger.log(sendCount + "통 발송 완료. 미발송: " + (emailList.length - sendCount) + "통");

    한도 초과 시 에러가 발생하면 나머지 코드도 모두 중단됩니다. 반드시 사전에 확인하세요.

    ✅ 스스로 점검하기¶

    아래 체크리스트를 하나씩 확인해 보세요.

    • MailApp.sendEmail()로 본인 이메일에 테스트 메일을 발송하고 수신을 확인했다
    • 객체 파라미터 방식({to, subject, htmlBody})으로 이메일을 발송할 수 있다
    • 스프레드시트에서 데이터를 읽어와 이메일 본문에 포함하는 전체 흐름을 이해했다
    • getRemainingDailyQuota()로 남은 발송 횟수를 확인하는 방법을 알고 있다
    • HTML 본문은 body가 아닌 htmlBody에 넣어야 한다는 것을 알고 있다
    • 시트 이름 불일치로 인한 null 에러를 예방하는 방법을 알고 있다
