    실전 프로젝트 ② – 학부모 소통 자동화 파이프라인¶

    Part 6: [2권] 통합 활용과 확장 – 나만의 자동화 시스템 만들기 | 24차시

    🎯 이 장에서 배우는 것¶

    • 설문 수집 → 데이터 정리 → 개별 메일 발송을 하나의 워크플로우로 자동화할 수 있다
    • 폼 제출 트리거와 조건부 발송을 결합한 실시간 소통 시스템을 구축할 수 있다
    • 발송 이력 관리와 미발송 건 재처리를 자동화할 수 있다
    • 전체 파이프라인의 안정성을 점검하고 트러블슈팅할 수 있다

    💡 왜 이걸 배우나요?¶

    학교 현장이든, 학원이든, 교육 관련 비즈니스든 — 학부모 소통은 가장 반복적이면서도 실수가 치명적인 업무입니다.

    상담 신청이 들어오면 확인하고, 스프레드시트에 옮겨 적고, 상담 일정을 잡고, 확정 이메일을 보내고, 발송 여부를 체크하고… 한 학기에 수십~수백 건을 이렇게 처리하다 보면 누락은 필연입니다.

    🏭 파이프라인이라는 비유를 떠올려보세요.

    정수장에서 물이 들어오면 여과 → 소독 → 검사 → 배수가 자동으로 연결되듯, 우리의 소통 업무도 "폼 제출 → 데이터 정리 → 조건 확인 → 메일 발송 → 이력 기록"이 끊김 없이 흐르는 파이프라인이 되어야 합니다.

    이번 차시에서는 Google Forms + Google Sheets + Gmail + Apps Script를 엮어서, 폼 하나 제출되면 끝까지 자동으로 처리되는 완전한 파이프라인을 만듭니다. 23차시에서 익힌 개별 스킬들이 여기서 하나로 합쳐집니다.

    📚 핵심 개념¶

    개념 1: 자동화 파이프라인 설계¶

    🎯 비유: 공장의 컨베이어 벨트

    자동차 공장에서 차체가 컨베이어 벨트에 올라가면 용접 → 도색 → 조립 → 검수가 순서대로 진행됩니다. 중간에 사람이 일일이 옮기지 않아도 됩니다. 우리가 만들 파이프라인도 동일합니다.

    정확한 정의: 자동화 파이프라인이란, 데이터가 입력되는 시점부터 최종 결과물(메일 발송, 알림 등)이 완료되는 시점까지의 모든 처리 단계가 코드로 연결되어 자동 실행되는 워크플로우입니다.

    이번 프로젝트의 파이프라인 구조:

    flowchart LR A["📋 Google Forms\n학부모 상담 신청"] --> B["📊 Google Sheets\n응답 자동 수집"] B --> C["⚙️ Apps Script\n데이터 정리 & 검증"] C --> D{"🔀 조건 분기\n상담 확정 여부"} D -->|확정| E["📧 Gmail\n확정 메일 발송"] D -->|미확정| F["⏳ 대기열\n상태 '대기' 기록"] E --> G["✅ 발송 이력\n시간·상태 기록"] F --> H["🔄 재처리\n일괄 발송 대상"]

    각 단계가 이전 단계의 출력을 입력으로 받아 자동으로 이어집니다. 이것이 "파이프라인"이라 불리는 이유입니다.

    💼 실무 TIP: 파이프라인 설계 시 가장 먼저 할 일은 종이 한 장에 "입력 → 처리1 → 처리2 → … → 출력"을 그리는 것입니다. 코드부터 작성하면 중간에 빠진 단계를 발견하기 어렵습니다.

    📌 핵심 포인트: 파이프라인은 "자동 연결"이 핵심입니다. 각 단계 사이에 사람의 개입이 필요하다면, 그 지점이 자동화의 대상입니다.

    개념 2: 폼 제출 트리거 (onFormSubmit)¶

    🎯 비유: 현관 초인종

    누군가 초인종을 누르면 실내에서 벨이 울리고, 스마트 도어벨이라면 핸드폰에 알림까지 보내줍니다. 폼 제출 트리거는 바로 이 초인종입니다 — 누군가 폼을 제출하면, 지정해둔 함수가 자동으로 실행됩니다.

    정확한 정의: onFormSubmit 트리거는 Google Forms의 응답이 제출될 때 자동으로 특정 함수를 실행하는 이벤트 기반 트리거입니다. 폼 응답이 스프레드시트에 기록되는 시점에 발동합니다.

    트리거가 전달하는 이벤트 객체(e):

    flowchart TD A["이벤트 객체 e"] --> B["e.values\n제출된 값 배열"] A --> C["e.range\n기록된 셀 범위"] A --> D["e.namedValues\n질문-답변 쌍"] B --> B1["e.values[0]: 타임스탬프\ne.values[1]: 학부모 이름\ne.values[2]: 이메일\n..."] D --> D1["{'학부모 성함': ['김미정'],\n'이메일': ['kim@email.com'],\n...}"]
    • e.values: 배열 형태, 순서대로 접근 (인덱스 기반)
    • e.namedValues: 질문 텍스트가 키인 객체 (이름 기반, 더 안전)
    • e.range: 시트에서 해당 응답이 기록된 정확한 위치

    ⚠️ 주의사항: e.namedValues의 각 값은 배열입니다. e.namedValues['이메일']이 아니라 e.namedValues['이메일'][0]으로 접근해야 합니다.

    📌 핵심 포인트: 폼 제출 트리거는 "실시간 반응"의 핵심입니다. 설정해두면 24시간 자동으로 작동하며, 별도 서버 없이 Google 인프라에서 실행됩니다.

    개념 3: 조건부 발송 로직¶

    🎯 비유: 공항 수하물 분류 시스템

    공항에서 짐이 컨베이어 벨트를 타고 내려오면, 바코드를 읽어서 목적지별로 다른 라인으로 보냅니다. 서울행은 왼쪽, 부산행은 오른쪽. 우리의 조건부 발송도 동일합니다 — 데이터의 특정 값을 확인해서 다른 처리를 적용합니다.

    정확한 정의: 조건부 발송이란, 수집된 데이터의 특정 필드 값에 따라 발송 여부, 메일 내용, 발송 시점 등을 다르게 처리하는 로직입니다.

    이 프로젝트에서 사용할 조건 분기:

    flowchart TD A["새 폼 응답 도착"] --> B{"상담 유형 확인"} B -->|"대면 상담"| C{"희망 일시 확인"} B -->|"전화 상담"| D["전화 상담 안내 메일\n즉시 발송"] B -->|"서면 상담"| E["서면 양식 첨부 메일\n즉시 발송"] C -->|"일정 확정 가능"| F["대면 상담 확정 메일\n장소·시간 포함"] C -->|"일정 미확정"| G["상태: '대기'\n담당자 알림"]

    조건부 로직의 3대 요소:

    • 조건 판별 기준: 어떤 필드를 볼 것인가 (상담 유형, 희망 일시 등)
    • 분기 처리: 조건에 따라 어떤 행동을 할 것인가 (다른 템플릿, 발송 보류 등)
    • 예외 처리: 어떤 조건에도 해당하지 않을 때 어떻게 할 것인가 (기본 안내 발송)

    💼 실무 TIP: 조건이 3개를 넘어가면 if-else 체인 대신 객체 매핑(lookup table) 패턴을 사용하세요. 코드가 훨씬 깔끔해지고 조건 추가도 쉬워집니다.

    📌 핵심 포인트: 조건부 발송은 "상황에 맞는 소통"을 자동화합니다. 모든 사람에게 같은 메일을 보내는 것보다, 상황별 맞춤 메일이 만족도를 크게 높입니다.

    개념 4: 발송 이력 관리와 재처리¶

    🎯 비유: 택배 운송장 번호

    택배를 보내면 운송장 번호가 부여되고, "집화 → 배송 중 → 배달 완료"가 실시간 추적됩니다. 배달 실패 시 자동으로 재배달이 잡힙니다. 이메일 발송도 동일한 이력 관리 체계가 필요합니다.

    정확한 정의: 발송 이력 관리란, 각 메일 건에 대해 발송 시도 시각, 성공/실패 여부, 재시도 횟수 등을 기록하고, 실패 건을 자동으로 재처리하는 시스템입니다.

    이력 관리에 기록할 필드:

    • 발송상태: 대기 / 발송완료 / 발송실패 / 재발송완료
    • 발송시각: 실제 메일이 나간 시간 (타임스탬프)
    • 재시도횟수: 실패 후 몇 번 재시도했는지
    • 오류메시지: 실패 시 원인 (이메일 형식 오류, 일일 한도 초과 등)
    flowchart LR A["메일 발송 시도"] --> B{"성공?"} B -->|Yes| C["상태: 발송완료\n시각 기록"] B -->|No| D["상태: 발송실패\n오류 기록"] D --> E{"재시도 3회 미만?"} E -->|Yes| F["다음 실행 시\n자동 재시도"] E -->|No| G["상태: 발송포기\n담당자 알림"]

    ⚠️ 주의사항: Gmail의 일일 발송 한도는 일반 계정 기준 100통/일, Google Workspace는 1,500통/일입니다. 한도 초과 시 Exception이 발생하므로, 반드시 try-catch로 감싸고 이력에 기록해야 합니다.

    📌 핵심 포인트: 자동화 시스템에서 "보냈는지 안 보냈는지 모르는 상태"가 가장 위험합니다. 이력 관리는 자동화의 신뢰성을 보장하는 안전장치입니다.

    Step 1: 폼 & 시트 구조 설계¶

    먼저 Google Forms에서 학부모 상담 신청 폼을 만들고, 응답이 기록될 시트의 구조를 설계합니다.

    1-1. Google Forms 생성

    Google Drive에서 새로 만들기 → Google 설문지를 클릭하고, 다음 항목을 만드세요:

    • 폼 제목: "2025학년도 학부모 상담 신청"
    • 질문 1 (단답형): 학부모 성함 — 필수
    • 질문 2 (단답형): 이메일 주소 — 필수
    • 질문 3 (단답형): 자녀 이름 — 필수
    • 질문 4 (단답형): 자녀 학년/반 — 필수
    • 질문 5 (객관식): 상담 유형 — 대면 상담 / 전화 상담 / 서면 상담
    • 질문 6 (객관식): 희망 일시 — 3월 15일 10시 / 3월 15일 14시 / 3월 16일 10시 / 3월 16일 14시 / 기타
    • 질문 7 (장문형): 상담 내용 요약 — 선택

    💼 실무 TIP: 이메일 주소 필드에는 응답 확인(유효성 검사) 을 설정하세요. 설문지 편집에서 해당 질문 오른쪽 하단 ⋮ → 응답 확인 → "텍스트" / "이메일 주소"를 선택하면 잘못된 형식의 이메일을 사전에 걸러냅니다.

    1-2. 응답 스프레드시트 연결

    폼 편집 화면에서 응답 탭 → 스프레드시트에서 보기(초록색 아이콘) 를 클릭합니다. 새 스프레드시트가 생성되며, "설문지 응답 1"이라는 시트에 응답이 자동 기록됩니다.

    1-3. 관리용 열 추가

    스프레드시트를 열면 A열부터 H열까지 폼 응답이 기록됩니다. 여기에 관리용 열 4개를 오른쪽에 추가합니다:

    • I열: 발송상태 (대기 / 발송완료 / 발송실패)
    • J열: 발송시각
    • K열: 재시도횟수
    • L열: 비고 (오류 메시지 등)

    첫 번째 행(헤더)에 각각 발송상태, 발송시각, 재시도횟수, 비고를 입력하세요.

    1-4. 시트 구조 정리

    시트 이름을 알기 쉽게 변경합니다:

    • "설문지 응답 1" → 상담신청 (시트 탭 더블클릭하여 수정)

    열 매핑 정리 (코드에서 참조할 인덱스):

    • A열(0): 타임스탬프
    • B열(1): 학부모 성함
    • C열(2): 이메일 주소
    • D열(3): 자녀 이름
    • E열(4): 자녀 학년/반
    • F열(5): 상담 유형
    • G열(6): 희망 일시
    • H열(7): 상담 내용 요약
    • I열(8): 발송상태
    • J열(9): 발송시각
    • K열(10): 재시도횟수
    • L열(11): 비고

    💼 실무 TIP: 열 번호를 코드에서 직접 쓰면 나중에 열 순서가 바뀌었을 때 전체 코드를 수정해야 합니다. 상수로 정의해두면 한 곳만 바꾸면 되므로, Step 2에서 이 패턴을 적용합니다.

    Step 2: 핵심 함수 작성¶

    스프레드시트에서 확장 프로그램 → Apps Script를 클릭하여 스크립트 편집기를 엽니다.

    2-1. 설정 상수 정의

    // ============================================
// 🔧 설정 영역 - 여기만 수정하면 됩니다

const CONFIG = {

    PREFERRED: 6,    // G열: 희망 일시
    CONTENT: 7,      // H열: 상담 내용 요약
    STATUS: 8,       // I열: 발송상태
    SENT_TIME: 9,    // J열: 발송시각
    RETRY_COUNT: 10, // K열: 재시도횟수
    NOTE: 11         // L열: 비고
  },

  // 발송 상태값
  STATUS: {
    WAITING: '대기',
    SENT: '발송완료',
    FAILED: '발송실패',
    RETRY_SENT: '재발송완료',
    GIVE_UP: '발송포기'
  },

  // 재시도 최대 횟수

  // 발신자 표시 이름

    이렇게 상수를 분리하면, 학교 이름이 바뀌거나 열 순서가 변경되어도 CONFIG만 수정하면 됩니다.

    2-2. 폼 제출 시 자동 실행되는 메인 함수

    // ============================================
// 📋 메인 함수: 폼 제출 시 자동 실행
// ============================================

function onFormSubmitHandler(e) {
  try {
    // 1. 이벤트에서 데이터 추출
    const values = e.values;
    const row = e.range.getRow();

    // 2. 데이터 객체로 정리
    const data = {
      timestamp: values[CONFIG.COL.TIMESTAMP],
      parentName: values[CONFIG.COL.PARENT_NAME],
      email: values[CONFIG.COL.EMAIL],
      studentName: values[CONFIG.COL.STUDENT_NAME],
      classInfo: values[CONFIG.COL.CLASS_INFO],
      type: values[CONFIG.COL.TYPE],
      preferred: values[CONFIG.COL.PREFERRED],
      content: values[CONFIG.COL.CONTENT] || '(내용 없음)',
      row: row  // 시트에서의 행 번호
    };

    // 3. 이메일 유효성 검증
    if (!isValidEmail(data.email)) {
      updateStatus(row, CONFIG.STATUS.FAILED, '이메일 형식 오류: ' + data.email);
      return;
    }

    // 4. 조건부 발송 처리
    processAndSend(data);

  } catch (error) {
    // 5. 예상치 못한 오류 처리
    Logger.log('onFormSubmitHandler 오류: ' + error.message);

    // e.range가 있으면 상태 업데이트 시도
    if (e && e.range) {
      updateStatus(e.range.getRow(), CONFIG.STATUS.FAILED, '시스템 오류: ' + error.message);
    }
  }
}

    2-3. 유틸리티 함수들

    // ============================================
// 🛠️ 유틸리티 함수들
// ============================================

/**
 * 이메일 형식 검증
 */
function isValidEmail(email) {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return emailRegex.test(email);
}

/**
 * 시트의 특정 행 상태 업데이트
 */
function updateStatus(row, status, note) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet()
    .getSheetByName(CONFIG.SHEET_NAME);

  // I열: 발송상태
  sheet.getRange(row, CONFIG.COL.STATUS + 1).setValue(status);

  // J열: 발송시각 (발송완료 또는 재발송완료일 때만)
  if (status === CONFIG.STATUS.SENT || status === CONFIG.STATUS.RETRY_SENT) {
    sheet.getRange(row, CONFIG.COL.SENT_TIME + 1)
      .setValue(new Date());
  }

  // L열: 비고
  if (note) {
    sheet.getRange(row, CONFIG.COL.NOTE + 1).setValue(note);
  }
}

/**
 * 재시도 횟수 증가
 */
function incrementRetryCount(row) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet()
    .getSheetByName(CONFIG.SHEET_NAME);
  const cell = sheet.getRange(row, CONFIG.COL.RETRY_COUNT + 1);
  const current = cell.getValue() || 0;
  cell.setValue(current + 1);
  return current + 1;
}

    ⚠️ 주의사항: getRange(row, column)에서 column은 1부터 시작합니다. 그래서 CONFIG.COL.STATUS(0 기반 인덱스 8)에 1을 더해 9열로 접근합니다. 이 차이를 혼동하면 엉뚱한 열에 데이터가 기록됩니다.

    3-2. 템플릿에 데이터 삽입하는 함수

    /**
 * 템플릿의 플레이스홀더를 실제 데이터로 치환
 */
function fillTemplate(templateStr, data) {
  return templateStr
    .replace(/{parentName}/g, data.parentName)
    .replace(/{studentName}/g, data.studentName)
    .replace(/{classInfo}/g, data.classInfo)
    .replace(/{preferred}/g, data.preferred)
    .replace(/{content}/g, data.content);
}

    3-3. 조건부 처리 & 발송 함수

    // ============================================
// 🔀 조건부 처리 & 발송
// ============================================

function processAndSend(data) {
  const template = TEMPLATES[data.type];

  // 알 수 없는 상담 유형 처리
  if (!template) {
    updateStatus(data.row, CONFIG.STATUS.FAILED, 
      '알 수 없는 상담 유형: ' + data.type);
    return;
  }

  // 즉시 발송 가능 여부 확인
  if (!template.canSendImmediately(data)) {
    // "기타" 일시를 선택한 대면 상담 등 → 대기 상태로
    updateStatus(data.row, CONFIG.STATUS.WAITING, 
      '희망 일시 "기타" 선택 → 담당자 확인 필요');

    // 담당자에게 알림 메일 (선택사항)
    notifyAdmin(data);
    return;
  }

  // 메일 제목/본문 생성
  const subject = fillTemplate(template.subject, data);
  const body = fillTemplate(template.body(data), data);

  // 메일 발송 시도
  sendEmail(data.row, data.email, subject, body);
}

/**
 * 실제 메일 발송 (try-catch로 안전하게)
 */
function sendEmail(row, to, subject, body) {
  try {
    GmailApp.sendEmail(to, subject, body, {
      name: CONFIG.SENDER_NAME
    });

    // 성공 시 상태 업데이트
    updateStatus(row, CONFIG.STATUS.SENT, '정상 발송');
    Logger.log('✅ 발송 성공: ' + to);

  } catch (error) {
    // 실패 시 상태 업데이트
    updateStatus(row, CONFIG.STATUS.FAILED, error.message);
    Logger.log('❌ 발송 실패: ' + to + ' / ' + error.message);
  }
}

/**
 * 담당자에게 확인 요청 알림
 */
function notifyAdmin(data) {
  const adminEmail = Session.getActiveUser().getEmail();
  const subject = '[알림] 상담 일정 확인 필요 - ' + data.parentName + '님';
  const body = `
상담 신청이 접수되었으나, 일정 확정이 필요합니다.

• 학부모: ${data.parentName}
• 학생: ${data.studentName} (${data.classInfo})
• 상담 유형: ${data.type}
• 희망 일시: ${data.preferred}
• 스프레드시트 ${data.row}행을 확인하고, 일정 확정 후 수동 발송해 주세요.
  `.trim();

  try {
    GmailApp.sendEmail(adminEmail, subject, body, {
      name: '상담 자동화 시스템'
    });
  } catch (e) {
    Logger.log('관리자 알림 발송 실패: ' + e.message);
  }
}

    💼 실무 TIP: TEMPLATES 객체에 canSendImmediately 함수를 넣은 이유가 있습니다. 조건 판단 로직이 템플릿과 함께 관리되므로, 나중에 상담 유형을 추가할 때 해당 유형의 객체만 추가하면 됩니다. 이것이 "확장 가능한 설계"입니다.

    Step 4: 발송 이력 관리 & 미발송 건 재처리¶

    4-1. 미발송 건 일괄 재처리 함수

    트리거 실행 시점에 네트워크 문제나 Gmail 한도 초과로 실패한 건들을 모아서 다시 발송하는 함수입니다.

    // ============================================
// 🔄 미발송 건 재처리
// ============================================

function retryFailedEmails() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet()
    .getSheetByName(CONFIG.SHEET_NAME);
  const data = sheet.getDataRange().getValues();

  let retryCount = 0;
  let successCount = 0;
  let giveUpCount = 0;

  // 헤더(0행) 제외, 1행부터 순회
  for (let i = 1; i < data.length; i++) {
    const row = data[i];
    const status = row[CONFIG.COL.STATUS];

    // "발송실패" 상태인 건만 처리
    if (status !== CONFIG.STATUS.FAILED) continue;

    const currentRetry = row[CONFIG.COL.RETRY_COUNT] || 0;
    const sheetRow = i + 1; // 시트 행 번호 (1-based)

    // 최대 재시도 횟수 초과 확인
    if (currentRetry >= CONFIG.MAX_RETRY) {
      updateStatus(sheetRow, CONFIG.STATUS.GIVE_UP, 
        '재시도 ' + CONFIG.MAX_RETRY + '회 초과');
      giveUpCount++;
      continue;
    }

    // 재시도 횟수 증가
    incrementRetryCount(sheetRow);

    // 데이터 객체 재구성
    const retryData = {
      parentName: row[CONFIG.COL.PARENT_NAME],
      email: row[CONFIG.COL.EMAIL],
      studentName: row[CONFIG.COL.STUDENT_NAME],
      classInfo: row[CONFIG.COL.CLASS_INFO],
      type: row[CONFIG.COL.TYPE],
      preferred: row[CONFIG.COL.PREFERRED],
      content: row[CONFIG.COL.CONTENT] || '(내용 없음)',
      row: sheetRow
    };

    // 이메일 재검증
    if (!isValidEmail(retryData.email)) {
      updateStatus(sheetRow, CONFIG.STATUS.GIVE_UP, 
        '이메일 형식 오류 - 재처리 불가');
      giveUpCount++;
      continue;
    }

    // 템플릿으로 메일 재생성 & 발송
    const template = TEMPLATES[retryData.type];
    if (!template) {
      updateStatus(sheetRow, CONFIG.STATUS.GIVE_UP, 
        '알 수 없는 상담 유형');
      giveUpCount++;
      continue;
    }

    const subject = fillTemplate(template.subject, retryData);
    const body = fillTemplate(template.body(retryData), retryData);

    try {
      GmailApp.sendEmail(retryData.email, subject, body, {
        name: CONFIG.SENDER_NAME
      });
      updateStatus(sheetRow, CONFIG.STATUS.RETRY_SENT, 
        '재발송 성공 (시도 ' + (currentRetry + 1) + '회)');
      successCount++;
    } catch (error) {
      updateStatus(sheetRow, CONFIG.STATUS.FAILED, 
        '재발송 실패: ' + error.message);
    }

    retryCount++;

    // Gmail 한도 보호: 연속 발송 사이 1초 대기
    Utilities.sleep(1000);
  }

  // 처리 결과 로그
  Logger.log(`재처리 완료 - 시도: ${retryCount}, 성공: ${successCount}, 포기: ${giveUpCount}`);
}

    4-2. "대기" 상태 건 수동 확정 후 발송

    담당자가 시트에서 "대기" → "발송요청"으로 변경하면, 해당 건을 발송하는 함수입니다.

    /**
 * "대기" 상태에서 담당자가 일정 확정 후 수동 발송
 * I열을 "발송요청"으로 변경한 뒤 이 함수를 실행
 */
function sendWaitingEmails() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet()
    .getSheetByName(CONFIG.SHEET_NAME);
  const data = sheet.getDataRange().getValues();

  let sentCount = 0;

  for (let i = 1; i < data.length; i++) {
    const row = data[i];
    const status = row[CONFIG.COL.STATUS];

    if (status !== '발송요청') continue;

    const sheetRow = i + 1;
    const sendData = {
      parentName: row[CONFIG.COL.PARENT_NAME],
      email: row[CONFIG.COL.EMAIL],
      studentName: row[CONFIG.COL.STUDENT_NAME],
      classInfo: row[CONFIG.COL.CLASS_INFO],
      type: row[CONFIG.COL.TYPE],
      preferred: row[CONFIG.COL.PREFERRED],
      content: row[CONFIG.COL.CONTENT] || '(내용 없음)',
      row: sheetRow
    };

    const template = TEMPLATES[sendData.type];
    if (!template) continue;

    const subject = fillTemplate(template.subject, sendData);
    const body = fillTemplate(template.body(sendData), sendData);

    sendEmail(sheetRow, sendData.email, subject, body);
    sentCount++;

    Utilities.sleep(1000);
  }

  Logger.log('대기 건 발송 완료: ' + sentCount + '건');
}

    💼 실무 TIP: Utilities.sleep(1000)으로 메일 사이에 1초 간격을 두는 이유는 두 가지입니다. ① Gmail API 호출 빈도 제한 방지 ② 스팸으로 분류될 확률 감소. 대량 발송(50건 이상)이라면 2초로 늘리세요.

    Step 5: 트리거 연결 & 테스트¶

    이제 모든 함수가 준비되었으니, 트리거를 설정하여 실제로 작동하게 만듭니다.

    5-1. 폼 제출 트리거 설정

    스크립트 편집기에서 다음 함수를 실행하여 트리거를 설치합니다:

    // ============================================
// ⏰ 트리거 설정 함수 (최초 1회만 실행)
// ============================================

function setupTriggers() {
  // 기존 트리거 모두 제거 (중복 방지)
  const triggers = ScriptApp.getProjectTriggers();
  triggers.forEach(function(trigger) {
    ScriptApp.deleteTrigger(trigger);
  });

  // 1. 폼 제출 트리거: 폼이 제출될 때마다 자동 실행
  ScriptApp.newTrigger('onFormSubmitHandler')
    .forSpreadsheet(SpreadsheetApp.getActive())
    .onFormSubmit()
    .create();

  // 2. 시간 기반 트리거: 매일 오전 9시에 실패 건 재처리
  ScriptApp.newTrigger('retryFailedEmails')
    .timeBased()
    .atHour(9)
    .everyDays(1)
    .create();

  Logger.log('✅ 트리거 설정 완료');
  Logger.log('  - 폼 제출 트리거: onFormSubmitHandler');
  Logger.log('  - 일일 재처리 트리거: retryFailedEmails (매일 09:00)');
}

    실행 방법: 1. 스크립트 편집기 상단에서 setupTriggers 함수를 선택 2. ▶️ 실행 버튼 클릭 3. 최초 실행 시 권한 승인 팝업이 뜹니다 4. "고급" → "○○(안전하지 않음)(으)로 이동" → "허용" 클릭

    5-2. 테스트 실행

    테스트 순서:

    ① 정상 케이스 테스트 - 폼에 실제 데이터 입력하여 제출 (본인 이메일 사용) - 상담 유형: "전화 상담", 희망 일시: 구체적 날짜 선택 - 기대 결과: 즉시 메일 수신, 시트 I열 "발송완료", J열에 시각 기록

    ② 대기 케이스 테스트 - 상담 유형: "대면 상담", 희망 일시: "기타" 선택 - 기대 결과: I열 "대기", 담당자 알림 메일 수신

    ③ 오류 케이스 테스트 - 시트에서 이메일 주소를 일부러 잘못된 값으로 수동 수정 후 재처리 실행 - 기대 결과: I열 "발송실패", L열에 오류 메시지
