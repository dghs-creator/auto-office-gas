    Chapter 10. 담당자 자동 알림 ② – 조건부 알림과 정기 보고¶

    Part 3: 알림·소통 자동화 – 필요한 사람에게 정확히 전달하기

    🎯 이 장에서 배우는 것¶

    • 특정 조건(마감 임박, 미완료 등)이 충족될 때만 알림을 발송할 수 있다
    • 시간 기반 트리거를 설정하여 매일·매주 정기 보고를 자동화할 수 있다
    • HTML 형식으로 표가 포함된 보기 좋은 보고 이메일을 작성할 수 있다
    • 조건부 알림과 정기 보고를 결합하여 완전 자동 모니터링 시스템을 구축할 수 있다

    💡 왜 이걸 배우나요?¶

    9장에서 우리는 "특정 행이 변경되면 담당자에게 알림을 보내는" 기본 알림을 배웠습니다. 하지만 실무에서는 이런 요청이 훨씬 더 많습니다.

    "매일 아침 9시에 미제출자 명단만 뽑아서 메일로 보내주세요." "마감 3일 전인 항목만 자동으로 리마인드해주세요." "미완료 건이 없으면 메일을 보내지 마세요 — 괜히 스팸처럼 보이니까요."

    이것이 바로 조건부 알림과 정기 보고입니다. 단순 알림에서 한 단계 진화하여, "필요할 때만, 정해진 시간에, 정리된 형식으로" 전달하는 시스템을 만들어봅시다.

    🏢 CASE STUDY: 한 마케팅팀에서는 매주 월요일 아침마다 10분씩 들여 "지난주 미완료 업무"를 수작업으로 정리해 팀장에게 보고했습니다. 이 장의 내용을 적용하면, 월요일 오전 8시에 자동으로 정리된 보고서가 팀장 메일함에 도착합니다. 연간 약 8시간의 반복 작업이 사라집니다.

    📚 핵심 개념¶

    개념 1: 조건부 발송 — "할 말이 있을 때만 말하기"¶

    비유: 아파트 경비실을 떠올려보세요. 택배가 도착했을 때만 "택배 왔습니다" 방송을 합니다. 택배가 없는 날에는 방송하지 않죠. 매일 "오늘은 택배 없습니다"라고 방송하면 주민들이 짜증날 겁니다.

    정의: 조건부 발송이란, 데이터를 먼저 확인한 뒤 특정 조건을 만족하는 항목이 존재할 때만 알림을 발송하는 패턴입니다.

    핵심 구조:

    // 조건부 발송의 기본 뼈대
var 대상목록 = 조건에_맞는_데이터_필터링();

if (대상목록.length > 0) {
  // 알림 발송
  MailApp.sendEmail(수신자, 제목, 본문);
} else {
  // 아무것도 하지 않음 (또는 로그만 남김)
  Logger.log("발송 대상 없음 — 메일 미발송");
}

    실무 TIP: if (대상목록.length > 0) 이 한 줄이 "스팸 방지 장치"입니다. 이것 없이 매일 빈 메일이 발송되면, 수신자는 알림 자체를 무시하게 됩니다.

    개념 2: 시간 기반 트리거 — "알람 시계 설정하기"¶

    비유: 스마트폰 알람을 생각해보세요. "매일 아침 7시", "매주 월요일 9시"처럼 설정하면 자동으로 울립니다. Apps Script의 시간 기반 트리거도 정확히 같은 원리입니다.

    정의: Google Apps Script에서 제공하는 시간 기반 트리거(Time-driven Trigger)는 특정 시간 간격이나 특정 시각에 함수를 자동 실행하는 기능입니다.

    트리거 종류와 활용 시나리오:

    graph LR A["⏰ 시간 기반 트리거"] --> B["매일 실행<br/>예: 매일 오전 8~9시"] A --> C["매주 실행<br/>예: 매주 월요일 오전 9~10시"] A --> D["매월 실행<br/>예: 매월 1일"] A --> E["분 단위 실행<br/>예: 매 30분마다"] B --> B1["미제출자 리마인드"] C --> C1["주간 진행률 보고"] D --> D1["월간 실적 요약"] E --> E1["긴급 이슈 모니터링"]

    주의사항: Google Apps Script 트리거의 시간은 정확한 시각이 아니라 1시간 범위 내에서 실행됩니다. "오전 8시~9시"로 설정하면 8:00~8:59 사이 어느 시점에 실행됩니다. 분 단위 정확성이 필요하면 "매 1분" 또는 "매 5분" 트리거를 사용하고 코드 내에서 시각을 체크하세요.

    개념 3: HTML 이메일 — "보기 좋은 떡이 먹기도 좋다"¶

    비유: 같은 보고 내용이라도, 줄글로 쭉 나열한 것과 깔끔한 표로 정리한 것은 읽는 사람의 반응이 완전히 다릅니다. HTML 이메일은 "보고서를 예쁘게 포장하는 기술"입니다.

    정의: MailApp.sendEmail()에서 htmlBody 옵션을 사용하면, HTML 태그로 구성된 본문을 보낼 수 있습니다. 표, 색상, 볼드 처리 등이 모두 가능합니다.

    핵심 차이점:

    graph TB subgraph 일반텍스트["📄 일반 텍스트 이메일"] T1["미완료 항목:<br/>- 기획서 검토 (김철수, 6/15)<br/>- 계약서 작성 (박영희, 6/14)"] end subgraph HTML이메일["🎨 HTML 이메일"] T2["제목, 표, 색상 강조가 적용된<br/>깔끔한 보고서 형태"] end 일반텍스트 -->|"htmlBody 사용"| HTML이메일

    사용할 핵심 HTML 태그 4가지:

    • <table>: 데이터를 표로 정리
    • <tr>, <td>: 표의 행(row)과 셀(cell)
    • <span style="color:red">: 텍스트 색상 강조
    • <b>: 굵은 글씨

    개념 4: 마감 임박 계산 — "D-Day 카운트다운"¶

    비유: 항공권 예약 사이트에서 "출발 3일 전" 리마인드를 보내주는 것과 같습니다. 오늘 날짜와 마감일을 비교해서 D-3, D-1 같은 상태를 자동 판별합니다.

    정의: JavaScript의 Date 객체를 활용해 오늘 날짜와 목표 날짜의 차이를 밀리초 → 일 수로 변환하여 판단합니다.

    // D-Day 계산 공식
var 오늘 = new Date();
var 마감일 = new Date("2025-06-20");
var 차이_밀리초 = 마감일.getTime() - 오늘.getTime();
var 남은일수 = Math.ceil(차이_밀리초 / (1000 * 60 * 60 * 24));
// 남은일수가 3 이하이면 → 마감 임박!

    실무 TIP: Math.ceil()(올림)을 사용하는 이유는, 마감일 당일에도 "D-0" 또는 "D-1"로 잡혀서 리마인드가 발송되도록 하기 위함입니다.

    🔨 따라하기: "주간 미완료 업무 자동 보고 시스템" 구축¶

    실습 시나리오¶

    팀 프로젝트 관리 시트에서 매주 월요일 아침, 미완료 업무가 있을 때만 팀장에게 HTML 형식의 보고 메일을 자동 발송합니다.

    Step 1: 스프레드시트 준비¶

    Google 스프레드시트를 새로 만들거나, 기존 업무 관리 시트를 준비합니다.

    시트 이름: 업무현황

    구성 (1행은 헤더, 2행부터 데이터):

    • A열: 업무명
    • B열: 담당자
    • C열: 마감일 (날짜 형식, 예: 2025-06-20)
    • D열: 상태 (완료 / 진행중 / 미착수)
    • E열: 담당자 이메일

    샘플 데이터 (5행 정도 입력):

    • A2: 기획서 초안 작성 / B2: 김철수 / C2: 2025-06-18 / D2: 완료 / E2: chulsoo@example.com
    • A3: 디자인 시안 검토 / B3: 박영희 / C3: 2025-06-22 / D3: 진행중 / E3: younghee@example.com
    • A4: 계약서 발송 / B4: 이민수 / C4: 2025-06-19 / D4: 미착수 / E4: minsu@example.com
    • A5: 회의록 정리 / B5: 정수진 / C5: 2025-06-25 / D5: 진행중 / E5: sujin@example.com
    • A6: 예산안 제출 / B6: 김철수 / C6: 2025-06-20 / D6: 미착수 / E6: chulsoo@example.com

    Step 2: 미완료 항목 필터링 함수 작성¶

    확장 프로그램 > Apps Script를 열고, 아래 코드를 입력합니다.

    /**
 * 미완료 업무 목록을 배열로 반환하는 함수
 * 반환 형태: [{업무명, 담당자, 마감일, 상태, 남은일수}, ...]
 */
function getIncompleteItems() {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("업무현황");
  var data = sheet.getDataRange().getValues();
  var today = new Date();
  today.setHours(0, 0, 0, 0); // 시간 부분 제거 (날짜만 비교)

  var result = [];

  // 1행은 헤더이므로 i=1부터 시작
  for (var i = 1; i < data.length; i++) {
    var 업무명 = data[i][0];
    var 담당자 = data[i][1];
    var 마감일 = new Date(data[i][2]);
    var 상태 = data[i][3];

    // "완료"가 아닌 항목만 필터링
    if (상태 !== "완료" && 업무명 !== "") {
      var 남은일수 = Math.ceil((마감일.getTime() - today.getTime()) / (1000 * 60 * 60 * 24));

      result.push({
        업무명: 업무명,
        담당자: 담당자,
        마감일: Utilities.formatDate(마감일, "Asia/Seoul", "yyyy-MM-dd"),
        상태: 상태,
        남은일수: 남은일수
      });
    }
  }

  return result;
}

    실무 TIP: today.setHours(0, 0, 0, 0) — 이 한 줄이 매우 중요합니다. 시간 부분을 0으로 맞추지 않으면, 실행 시각에 따라 D-Day 계산이 달라질 수 있습니다.

    ⚠️ 자주 하는 실수¶

    실수 1: 날짜 비교 시 시간(time) 부분을 무시하지 않음¶

    // ❌ 잘못된 예 — 시간까지 비교되어 D-Day 계산이 부정확
var today = new Date(); // 2025-06-17T14:30:00

// ✅ 올바른 예 — 시간을 00:00:00으로 초기화
var today = new Date();
today.setHours(0, 0, 0, 0); // 2025-06-17T00:00:00

    오후에 실행하면 "D-1"이어야 할 항목이 "D-0"으로 계산될 수 있습니다.

    트리거 설정 함수를 여러 번 실행하면, 같은 함수에 트리거가 여러 개 붙어서 메일이 중복 발송됩니다.

MailApp.sendEmail({ to: 수신자, subject: 제목, htmlBody: html });

// ✅ 대체 텍스트 포함
MailApp.sendEmail({ to: 수신자, subject: 제목, body: "미완료 업무 " + items.length + "건 — HTML 메일을 확인해주세요.", htmlBody: html });

    실수 4: 빈 행이 포함된 시트에서 무한 반복¶

    getDataRange()는 데이터가 있는 마지막 행까지만 가져오지만, 중간에 빈 행이 있으면 그 행도 포함됩니다. 반드시 빈 값 체크를 넣으세요.

    if (상태 === "완료" || 업무명 === "") continue; // 빈 행 건너뛰기

    ✅ 스스로 점검하기¶

    아래 항목을 하나씩 체크해보세요.

    • getIncompleteItems() 함수를 실행하면 미완료 항목만 정확히 필터링되는가?
    • sendWeeklyReport() 실행 시, 모든 업무가 "완료"일 때 메일이 발송되지 않는가?
    • 수신된 HTML 이메일에서 표가 깨지지 않고 잘 보이는가?
    • 마감 초과 항목은 빨간 배경, D-3 이내는 노란 배경으로 표시되는가?
    • ⏰ 트리거 메뉴에서 주간 보고 트리거가 정확히 1개만 등록되어 있는가?
    • sendDeadlineReminders() 실행 시, D-3 이내인 담당자에게만 개별 메일이 발송되는가?
