    설문·피드백 자동 정리 – 응답 통계와 분석을 한 번에¶

    Part 2 | 데이터 수집·정리 자동화 · 8차시 (총 25차시 중)

    🎯 이 장에서 배우는 것¶

    • 구글 폼 설문 응답을 항목별로 자동 집계하여 통계표를 생성할 수 있다
    • 주관식 응답을 키워드 기반으로 분류하는 스크립트를 작성할 수 있다
    • 설문 결과를 차트용 데이터로 가공하는 코드를 활용할 수 있다
    • 설문 분석 자동화 워크플로를 실무에 적용할 수 있다

    💡 왜 이걸 배우나요?¶

    상황: 마케팅팀 김 대리는 고객 만족도 설문을 실시했습니다. 응답이 247개 들어왔는데, 객관식 5개 문항 집계에 주관식 2개 문항 분류까지 해야 합니다. 수작업으로 하면 반나절, 실수라도 하면 다시 처음부터…

    이런 경험, 익숙하시죠?

    설문 응답 정리는 "단순하지만 양이 많은" 업무의 대표 사례입니다. 객관식은 일일이 세야 하고, 주관식은 읽고 분류해야 합니다. 100개까지는 참을 수 있지만, 200개가 넘어가면 집중력이 떨어지고 실수가 생깁니다.

    Apps Script로 자동화하면 247개든 2,470개든 10초 안에 집계가 끝납니다. 이번 장에서는 설문 응답 시트를 통계표와 차트용 데이터로 변환하는 전체 과정을 다룹니다.

    📚 핵심 개념¶

    개념 1: 빈도 집계(Frequency Count) 🧮¶

    비유: 선거 개표를 떠올려 보세요. 투표함을 열고 한 장씩 넘기며 후보별로 정(正) 자를 긋습니다. 설문 객관식 집계도 완전히 같은 원리입니다. 다만, 코드가 여러분 대신 정(正) 자를 그어주는 것이죠.

    정의: 각 선택지가 몇 번 선택되었는지 세어 빈도수와 비율을 계산하는 작업

    예시: "서비스에 만족하십니까?" 문항에서 - 매우 만족 → 89명 (36.0%) - 만족 → 112명 (45.3%) - 보통 → 31명 (12.6%) - 불만족 → 15명 (6.1%)

    핵심 포인트: 빈도 집계의 본질은 "같은 값끼리 묶어서 세기"입니다. JavaScript 객체(Object)의 키-값 구조가 이 작업에 딱 맞습니다.

    개념 2: 키워드 태깅(Keyword Tagging) 🏷️¶

    비유: 이메일을 받으면 제목을 훑어보고 "긴급", "참고", "나중에" 같은 라벨을 붙이잖아요? 주관식 응답에도 같은 원리를 적용합니다. 미리 정한 키워드가 응답에 포함되어 있으면 해당 태그를 자동으로 붙여주는 것입니다.

    정의: 텍스트 응답에서 사전에 정의한 키워드 목록과 대조하여 카테고리를 자동 부여하는 방법

    예시: "가격이 비싸서 재구매하기 어려울 것 같아요" → 가격 키워드 감지 → "가격/비용" 태그 부여

    핵심 포인트: 키워드 태깅은 완벽한 분류가 아니라 1차 분류입니다. 80% 정도만 자동 분류해도 수작업 시간이 극적으로 줄어듭니다.

    개념 3: 피벗 형태 데이터 구조 📊¶

    비유: 원재료(생 응답)를 바로 요리(차트)에 쓸 수 없듯이, 응답 데이터도 차트에 넣기 전에 "손질"이 필요합니다. 행은 항목명, 열은 수치(빈도, 비율)로 깔끔하게 정리된 구조가 피벗 형태입니다.

    정의: 원본 데이터를 집계·요약하여 행과 열이 분석 축과 수치로 구성된 요약 테이블

    flowchart LR A["원본 응답\n(247행 × 7열)"] --> B["빈도 집계\n(항목별 count)"] B --> C["피벗 테이블\n(항목 / 빈도 / 비율)"] C --> D["📊 차트 생성"]

    핵심 포인트: 차트가 요구하는 데이터 구조를 먼저 파악하고, 그 형태에 맞춰 코드를 작성하는 것이 순서입니다.

    개념 4: 결과 시트 자동 생성 📋¶

    비유: 보고서를 쓸 때 빈 종이에서 시작하는 것보다 양식이 있으면 훨씬 빠르죠? 코드가 새 시트를 만들고, 헤더를 넣고, 데이터를 채워넣는 것까지 자동으로 해줍니다.

    정의: 분석 결과를 별도의 시트에 자동으로 생성하여 원본 데이터와 분리된 깔끔한 통계표를 만드는 과정

    핵심 포인트: 원본 시트는 절대 건드리지 않습니다. 항상 새 시트에 결과를 출력하는 것이 안전한 자동화의 기본 원칙입니다.

    🔨 따라하기¶

    사전 준비: 실습용 설문 응답 시트 만들기¶

    실습을 위해 구글 스프레드시트에 아래와 같은 구조의 시트가 필요합니다. 시트 이름은 "설문응답"으로 지정하세요.

    1행(헤더) 구성: - A열: 타임스탬프 - B열: 전반적 만족도 (매우만족/만족/보통/불만족/매우불만족) - C열: 재이용 의향 (예/아니오/모르겠다) - D열: 추천 의향 (1~10 숫자) - E열: 개선사항 (주관식)

    2행부터 샘플 데이터 10~20행 정도 입력합니다. (실제 설문 데이터가 있다면 그대로 사용하세요)

    💼 실무 TIP: 구글 폼과 연결된 스프레드시트는 자동으로 이 구조가 됩니다. 폼 응답 시트의 이름만 확인하면 바로 적용 가능합니다.

    Step 1: 객관식 응답 빈도 집계 함수 만들기¶

    Apps Script 편집기를 열고 (확장 프로그램 > Apps Script) 아래 코드를 입력합니다.

    /**
 * 특정 열의 객관식 응답을 빈도 집계하는 함수
 * @param {string} sheetName - 응답 시트 이름
 * @param {number} colIndex - 집계할 열 번호 (1부터 시작)
 * @return {Object} {항목명: 빈도수} 형태의 객체
 */
function countResponses(sheetName, colIndex) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(sheetName);
  var data = sheet.getRange(2, colIndex, sheet.getLastRow() - 1, 1).getValues();

  var counts = {};
  for (var i = 0; i < data.length; i++) {
    var answer = String(data[i][0]).trim();
    if (answer === "" || answer === "undefined") continue; // 빈 응답 건너뛰기
    counts[answer] = (counts[answer] || 0) + 1;
  }
  return counts;
}

    코드 핵심 설명: - getRange(2, colIndex, ...) → 2행부터 읽어 헤더를 제외합니다 - counts[answer] = (counts[answer] || 0) + 1 → 이 한 줄이 빈도 집계의 핵심입니다. 해당 답변이 처음 나오면 0+1=1, 이미 있으면 기존값+1

    핵심 포인트: 이 함수는 어떤 객관식 문항에든 재사용할 수 있습니다. 열 번호만 바꾸면 됩니다.

    Step 2: 빈도수를 비율(%)로 변환하기¶

    집계된 빈도수에 비율을 추가하는 함수를 작성합니다.

    /**
 * 빈도 객체에 비율(%) 정보를 추가하여 배열로 반환
 * @param {Object} counts - {항목명: 빈도수} 객체
 * @return {Array} [[항목명, 빈도수, 비율], ...] 2차원 배열
 */
function addPercentage(counts) {
  var total = 0;
  for (var key in counts) {
    total += counts[key];
  }

  var result = [];
  for (var key in counts) {
    var freq = counts[key];
    var pct = ((freq / total) * 100).toFixed(1) + "%";
    result.push([key, freq, pct]);
  }

  // 빈도수 내림차순 정렬
  result.sort(function(a, b) { return b[1] - a[1]; });
  return result;
}

    💼 실무 TIP: .toFixed(1)은 소수점 첫째 자리까지 표시합니다. 보고서에 넣을 때는 toFixed(1)이면 충분합니다. 소수점이 길면 오히려 가독성이 떨어집니다.

    Step 3: 주관식 응답 키워드 태깅¶

    주관식 응답을 키워드 사전 기반으로 자동 분류합니다.

    /**
 * 주관식 응답에 키워드 기반 태그를 부여
 * @param {string} sheetName - 시트 이름
 * @param {number} colIndex - 주관식 열 번호
 * @return {Array} [[원문, 태그], ...] 배열
 */
function tagOpenResponses(sheetName, colIndex) {
  // ★ 키워드 사전: 실무에 맞게 수정하세요
  var keywordMap = {
    "가격/비용": ["가격", "비용", "비싸", "저렴", "할인", "요금"],
    "서비스/응대": ["서비스", "응대", "친절", "불친절", "직원", "상담"],
    "품질/성능": ["품질", "성능", "퀄리티", "기능", "속도", "느리"],
    "접근성/편의": ["접근", "편리", "불편", "위치", "주차", "교통"],
    "기타": [] // 어디에도 매칭 안 되면 기타
  };

  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(sheetName);
  var data = sheet.getRange(2, colIndex, sheet.getLastRow() - 1, 1).getValues();

  var result = [];
  for (var i = 0; i < data.length; i++) {
    var text = String(data[i][0]).trim();
    if (text === "" || text === "undefined") continue;

    var tags = [];
    for (var category in keywordMap) {
      var keywords = keywordMap[category];
      for (var k = 0; k < keywords.length; k++) {
        if (text.indexOf(keywords[k]) !== -1) {
          tags.push(category);
          break; // 한 카테고리에서 하나만 매칭되면 다음 카테고리로
        }
      }
    }

    if (tags.length === 0) tags.push("기타");
    result.push([text, tags.join(", ")]);
  }
  return result;
}

    코드 핵심 설명: - keywordMap → 카테고리별 키워드를 사전처럼 정의합니다 - text.indexOf(keywords[k]) !== -1 → 응답 텍스트에 키워드가 포함되어 있는지 확인 - 하나의 응답에 여러 태그가 붙을 수 있습니다 (예: "가격도 비싸고 서비스도 불친절" → "가격/비용, 서비스/응대")

    ⚠️ 주의사항: 키워드 사전은 설문 주제에 따라 반드시 커스터마이징하세요. 위 예시는 고객 만족도 설문 기준입니다.

    Step 4: 결과를 새 시트에 자동 출력하기¶

function analyzeSurvey() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();

  // 기존 결과 시트가 있으면 삭제 후 새로 생성
  var resultSheet = ss.getSheetByName("분석결과");
  if (resultSheet) ss.deleteSheet(resultSheet);
  resultSheet = ss.insertSheet("분석결과");

  }

  row++;

  resultSheet.getRange(row, 1).setValue("📈 개선사항 카테고리별 집계").setFontWeight("bold").setFontSize(12);
  row++;

  row++;

  var tagCounts = {};
  for (var i = 0; i < taggedData.length; i++) {
    var tags = taggedData[i][1].split(", ");
    for (var j = 0; j < tags.length; j++) {
      tagCounts[tags[j]] = (tagCounts[tags[j]] || 0) + 1;
    }

function createChart() {

/** 객관식 빈도 집계 */
function countResponses(sheetName, colIndex) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(sheetName);
  var data = sheet.getRange(2, colIndex, sheet.getLastRow() - 1, 1).getValues();
  var counts = {};
  for (var i = 0; i < data.length; i++) {
    var answer = String(data[i][0]).trim();
    if (answer === "" || answer === "undefined") continue;
    counts[answer] = (counts[answer] || 0) + 1;
  }
  return counts;
}

/** 빈도 → 비율 변환 */
function addPercentage(counts) {
  var total = 0;
  for (var key in counts) total += counts[key];
  var result = [];
  for (var key in counts) {
    var freq = counts[key];
    var pct = ((freq / total) * 100).toFixed(1) + "%";
    result.push([key, freq, pct]);
  }
  result.sort(function(a, b) { return b[1] - a[1]; });
  return result;
}

/** 주관식 키워드 태깅 */
function tagOpenResponses(sheetName, colIndex) {
  var keywordMap = {
    "가격/비용": ["가격", "비용", "비싸", "저렴", "할인", "요금"],
    "서비스/응대": ["서비스", "응대", "친절", "불친절", "직원", "상담"],
    "품질/성능": ["품질", "성능", "퀄리티", "기능", "속도", "느리"],
    "접근성/편의": ["접근", "편리", "불편", "위치", "주차", "교통"]
  };
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(sheetName);
  var data = sheet.getRange(2, colIndex, sheet.getLastRow() - 1, 1).getValues();
  var result = [];
  for (var i = 0; i < data.length; i++) {
    var text = String(data[i][0]).trim();
    if (text === "" || text === "undefined") continue;
    var tags = [];
    for (var category in keywordMap) {
      var keywords = keywordMap[category];
      for (var k = 0; k < keywords.length; k++) {
        if (text.indexOf(keywords[k]) !== -1) {
          tags.push(category);
          break;
        }
      }
    }
    if (tags.length === 0) tags.push("기타");
    result.push([text, tags.join(", ")]);
  }
  return result;
}

    ⚠️ 자주 하는 실수¶

    실수 1: 시트 이름 불일치 🔤¶

    증상: TypeError: Cannot call method "getRange" of null 원인: 코드의 "설문응답"과 실제 시트 탭 이름이 다릅니다. 구글 폼 연결 시 자동 생성되는 시트 이름은 "설문지 응답 1" 형태인 경우가 많습니다. 해결: 시트 탭 이름을 정확히 확인하고, 코드의 문자열을 수정하세요. 공백과 띄어쓰기도 정확히 일치해야 합니다.

    실수 2: 빈 응답 처리 누락 🕳️¶

    증상: 통계에 빈 문자열("")이 하나의 항목으로 집계됩니다. 원인: 응답하지 않은 문항이 빈 셀로 남아있는데, 이를 필터링하지 않았습니다. 해결: 코드에 이미 if (answer === "") continue;를 넣어두었습니다. 혹시 " " (공백 한 칸)이 있을 수 있으니 .trim()도 꼭 적용하세요.

    실수 3: 키워드 사전을 설문 주제에 맞게 안 바꿈 📋¶

    증상: 대부분의 주관식 응답이 "기타"로 분류됩니다. 원인: 예시 키워드가 고객 만족도 기준이라 다른 설문(직원 만족도, 행사 피드백 등)에는 맞지 않습니다. 해결: 주관식 응답을 10개 정도 직접 읽어본 후, 자주 등장하는 단어를 키워드 사전에 추가하세요. 키워드 사전 커스터마이징이 이 기능의 핵심입니다.

    실수 4: 열 번호를 잘못 지정 🔢¶

    증상: 만족도를 집계해야 하는데 타임스탬프가 집계됩니다. 원인: countResponses("설문응답", 2)에서 열 번호 2가 실제 시트의 구조와 다릅니다. 해결: 스프레드시트에서 해당 열이 몇 번째인지 직접 세어보세요. A=1, B=2, C=3... 구글 폼이 중간에 문항을 추가하면 열 순서가 바뀔 수 있습니다.

    ✅ 스스로 점검하기¶

    아래 항목을 모두 체크할 수 있다면 이번 차시를 완료한 것입니다:

    • countResponses 함수의 원리를 설명할 수 있다 (JavaScript 객체로 빈도 집계)
    • 키워드 사전(keywordMap)을 내 설문에 맞게 수정할 수 있다
    • analyzeSurvey()를 실행하여 "분석결과" 시트가 생성되는 것을 확인했다
    • 객관식 3개 문항 이상의 빈도·비율이 정확히 출력되었다
    • 주관식 응답에 태그가 자동 부여되었고, "기타" 비율이 30% 이하이다
    • 분석 대상 열 번호를 바꿔서 다른 문항도 집계해보았다

    ① 고객 만족도 설문 — 분기마다 실시하는 NPS 설문 응답 500건을 자동 집계. 키워드 사전에 "배송", "포장", "CS" 등 추가

    ③ 직원 만족도 조사 — 반기 1회 실시. "복지", "급여", "성장", "소통", "워라밸" 키워드로 태깅 후 부서별 비교 분석
