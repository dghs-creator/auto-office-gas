    Chapter 05: 트리거 설정 – 자동 실행으로 손 놓고 맡기기¶

    🎯 이 장에서 배우는 것¶

    • 시간 기반 트리거를 설정하여 스크립트를 정해진 시각에 자동 실행할 수 있다
    • 이벤트 기반 트리거(폼 제출 등)를 설정하여 특정 동작에 반응하는 자동화를 구현할 수 있다
    • 트리거를 생성·확인·삭제하는 전체 관리 프로세스를 수행할 수 있다
    • 트리거 오류를 확인하고 대응하는 방법을 숙지할 수 있다

    💡 왜 이걸 배우나요?¶

    지금까지 우리는 스크립트를 작성하고 직접 "실행" 버튼을 눌러서 동작시켰습니다. 하지만 현실을 떠올려 보세요.

    "매일 아침 8시에 출결 현황을 정리해줘" "구글 폼에 응답이 들어올 때마다 즉시 집계 시트를 업데이트해줘" "매주 월요일 아침에 주간 업무 요약을 자동으로 만들어줘"

    이런 요청을 받을 때마다 매번 컴퓨터 앞에 앉아서 버튼을 누를 수는 없습니다. 트리거(Trigger)는 바로 이 문제를 해결합니다.

    트리거를 한마디로 정의하면:

    🔔 "내가 없어도 스크립트가 알아서 실행되게 만드는 예약 장치"

    스마트폰 알람을 생각해 보세요. 한 번 설정해두면 매일 아침 정해진 시간에 알아서 울립니다. 트리거도 똑같습니다. 한 번 설정해두면 정해진 시간 또는 특정 이벤트가 발생했을 때 스크립트가 자동으로 실행됩니다.

    이번 장을 마치면 여러분은 "내가 자는 동안에도 일하는 스크립트"를 갖게 됩니다.

    📚 핵심 개념¶

    개념 1: 트리거란 무엇인가 – "자동 알람 시계"¶

    🎯 비유로 시작

    회사 건물의 자동 조명 시스템을 떠올려 보세요.

    • 타이머 조명: 매일 오전 7시에 자동으로 켜지고, 오후 10시에 꺼집니다 → 시간 기반 트리거
    • 센서 조명: 사람이 복도에 들어서면 자동으로 켜집니다 → 이벤트 기반 트리거

    둘 다 사람이 직접 스위치를 누를 필요가 없다는 공통점이 있습니다. 트리거도 마찬가지입니다.

    📖 정확한 정의

    트리거(Trigger)란 특정 조건이 충족되었을 때 지정된 함수를 자동으로 실행시키는 앱스 스크립트의 기능입니다. 앱스 스크립트에서 사용할 수 있는 트리거는 크게 두 종류입니다.

    1. 시간 기반 트리거 (Time-driven Trigger) - 정해진 시간 간격 또는 특정 시각에 실행 - 예: 매일 오전 8시, 매시간, 매주 월요일

    2. 이벤트 기반 트리거 (Event-driven Trigger) - 특정 동작(이벤트)이 발생했을 때 실행 - 예: 폼 응답 제출, 스프레드시트 편집, 문서 열기

    💻 예시로 확인

    flowchart LR A["트리거 Trigger"] --> B["시간 기반"] A --> C["이벤트 기반"] B --> B1["매 분/시간마다"] B --> B2["매일 특정 시각"] B --> B3["매주 특정 요일"] B --> B4["매월 특정 날짜"] C --> C1["폼 제출 시"] C --> C2["스프레드시트 열기"] C --> C3["스프레드시트 편집 시"] C --> C4["캘린더 업데이트 시"]

    실무 TIP: 대부분의 업무 자동화는 "시간 기반 + 폼 제출" 이 두 가지만으로 80% 이상 해결됩니다. 이번 장에서는 이 두 가지에 집중합니다.

    개념 2: 시간 기반 트리거 – "매일 아침 울리는 알람"¶

    🎯 비유로 시작

    매일 아침 7시에 울리는 알람을 설정할 때 우리가 하는 일을 생각해 봅시다.

    1. 알람 앱을 엽니다 → 트리거 메뉴를 엽니다
    2. 시간을 "오전 7시"로 설정합니다 → 실행 시각을 설정합니다
    3. "매일 반복"을 선택합니다 → 반복 주기를 설정합니다
    4. "저장"을 누릅니다 → 트리거를 저장합니다

    📖 정확한 정의

    시간 기반 트리거는 시계를 기준으로 동작합니다. 설정할 수 있는 반복 주기는 다음과 같습니다.

    반복 주기 옵션

    • 특정 날짜와 시간: 한 번만 실행 (일회성 예약)
    • 분 단위 타이머: 1분 / 5분 / 10분 / 15분 / 30분마다
    • 시간 단위 타이머: 1시간 / 2시간 / 4시간 / 6시간 / 8시간 / 12시간마다
    • 일 단위 타이머: 매일 특정 시간대 (예: 오전 8시~9시 사이)
    • 주 단위 타이머: 매주 특정 요일, 특정 시간대
    • 월 단위 타이머: 매월 특정 날짜, 특정 시간대

    💻 예시로 확인

    주의사항: 시간 기반 트리거는 정확한 분 단위 시각을 지정할 수 없습니다. "오전 8시~9시 사이"처럼 1시간 범위 안에서 실행됩니다. "정확히 8시 00분"은 보장되지 않습니다. 이것은 구글의 서버 부하 분산 정책 때문입니다.

    flowchart TD subgraph 시간기반["⏰ 시간 기반 트리거 설정 흐름"] S1["1. 실행할 함수 선택"] --> S2["2. 이벤트 소스: '시간 기반'"] S2 --> S3["3. 트리거 유형 선택\n(일/주/월 타이머)"] S3 --> S4["4. 시간대 또는 간격 선택"] S4 --> S5["5. 저장"] end

    핵심 포인트: 시간 기반 트리거는 "특정 시간대에 자동 실행"이 핵심입니다. 정확한 분 단위 실행이 필요하다면, 1분 간격 타이머를 설정한 후 코드 안에서 현재 시각을 확인하는 방법을 사용합니다. (이 방법은 "더 해보기" 섹션에서 다룹니다.)

    개념 3: 이벤트 기반 트리거 – "문이 열리면 켜지는 센서등"¶

    🎯 비유로 시작

    편의점 입구에 있는 자동문을 생각해 보세요. 사람이 다가가면 센서가 감지해서 문이 자동으로 열립니다. 시간이 아니라 "사람이 다가왔다"는 이벤트에 반응하는 것입니다.

    이벤트 기반 트리거도 마찬가지입니다. "몇 시에"가 아니라 "무슨 일이 일어났을 때" 스크립트가 실행됩니다.

    📖 정확한 정의

    이벤트 기반 트리거는 구글 워크스페이스 앱에서 발생하는 특정 동작을 감지하여 함수를 실행합니다.

    주요 이벤트 유형

    • 스프레드시트 → 열기(On open): 스프레드시트를 열 때 실행
    • 스프레드시트 → 편집(On edit): 셀을 편집할 때 실행
    • 스프레드시트 → 값 변경(On change): 구조적 변경(행 추가, 시트 삭제 등) 시 실행
    • 스프레드시트 → 폼 제출(On form submit): 연결된 구글 폼에 응답이 제출될 때 실행
    • 폼 → 폼 제출(On form submit): 폼 자체에서 응답이 제출될 때 실행

    개념 4: 트리거 관리 – "설치한 알람을 점검하고 수리하기"¶

    🎯 비유로 시작

    알람을 설정했는데 배터리가 다 되면 울리지 않습니다. 또한 이사한 후에는 이전 집 알람을 해제해야 합니다. 트리거도 마찬가지로 점검·수정·삭제·오류 확인이 필요합니다.

    📖 정확한 정의

    트리거 관리란 설정된 트리거의 상태 확인, 오류 로그 확인, 불필요한 트리거 삭제를 수행하는 일련의 과정입니다.

    관리가 필요한 이유

    • 트리거 할당량: 무료 계정은 프로젝트당 최대 20개 트리거까지 설정 가능
    • 실행 할당량: 하루 트리거 실행 총 시간은 90분(무료 계정 기준)으로 제한
    • 오류 누적: 트리거 실행 중 오류가 반복되면 구글이 자동으로 트리거를 비활성화할 수 있음
    • 중복 생성: 같은 트리거를 실수로 여러 번 만들면 함수가 중복 실행됨

    💻 관리 포인트 정리

    주의사항: 앱스 스크립트에서 트리거는 수정이 불가능합니다. 설정을 변경하려면 기존 트리거를 삭제한 후 새로 생성해야 합니다. 알람 시간을 바꾸려면 기존 알람을 지우고 새로 설정하는 것과 같습니다.

    핵심 포인트: 트리거는 "설정하고 끝"이 아닙니다. 주기적으로 실행 로그를 확인하고, 불필요한 트리거를 정리하는 습관이 중요합니다.

    🔨 따라하기: 실무 자동화 3종 세트 만들기¶

    이제 실제로 트리거를 설정해 봅시다. 세 가지 실무 시나리오를 단계별로 실습합니다.

    실습 준비: 스프레드시트 만들기¶

    본격적인 실습에 앞서, 공통으로 사용할 스프레드시트를 만들겠습니다.

    1. 구글 드라이브에서 새 스프레드시트를 생성합니다.

    2. 파일 이름을 트리거 실습으로 변경합니다.

    3. 첫 번째 시트 이름을 출결현황으로 바꿉니다. (시트 탭을 더블클릭하면 이름 변경 가능)

    4. 다음과 같이 데이터를 입력합니다.

    • A1: 이름 / B1: 부서 / C1: 출근시간 / D1: 상태
    • A2: 김철수 / B2: 영업팀 / C2: (비워둡니다) / D2: (비워둡니다)
    • A3: 이영희 / B3: 마케팅팀 / C3: (비워둡니다) / D3: (비워둡니다)
    • A4: 박민수 / B4: 개발팀 / C4: (비워둡니다) / D4: (비워둡니다)
    • A5: 최지현 / B5: 인사팀 / C5: (비워둡니다) / D5: (비워둡니다)

    5. 두 번째 시트를 추가하고 이름을 주간요약으로 만듭니다.

    • A1: 작성일시 / B1: 총인원 / C1: 출근완료 / D1: 미출근

    Step 1: 매일 아침 출결 현황 자동 초기화 (시간 기반 트리거)¶

    시나리오: 매일 아침 자동으로 출결 시트의 "출근시간"과 "상태" 컬럼을 초기화합니다. 새로운 하루가 시작될 때마다 깨끗한 출결부가 준비되는 것입니다.

    1단계: 스크립트 작성

    스프레드시트 상단 메뉴에서 확장 프로그램 → Apps Script를 클릭하여 스크립트 편집기를 엽니다.

    기존 코드를 모두 지우고 다음 코드를 붙여넣습니다:

    /**
 * 매일 아침 출결 현황을 초기화하는 함수
 * 출근시간(C열)과 상태(D열)를 비우고, 상태를 "미출근"으로 설정합니다.
 */
function resetAttendance() {
  // 1. 스프레드시트와 시트 가져오기
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName('출결현황');

  // 2. 데이터가 있는 마지막 행 확인 (1행은 헤더니까 2행부터)
  var lastRow = sheet.getLastRow();

  // 3. 데이터가 없으면 종료
  if (lastRow < 2) {
    Logger.log('초기화할 데이터가 없습니다.');
    return;
  }

  // 4. C열(출근시간)을 모두 비우기
  var timeRange = sheet.getRange(2, 3, lastRow - 1, 1); // 2행부터, 3열(C), 데이터 행 수만큼, 1열
  timeRange.clearContent();

  // 5. D열(상태)을 모두 "미출근"으로 설정
  var statusRange = sheet.getRange(2, 4, lastRow - 1, 1); // 2행부터, 4열(D)
  var statusValues = [];
  for (var i = 0; i < lastRow - 1; i++) {
    statusValues.push(['미출근']);
  }
  statusRange.setValues(statusValues);

  // 6. 실행 로그 기록
  Logger.log('출결 현황 초기화 완료: ' + new Date().toLocaleString());
}

    2단계: 코드 먼저 테스트

    트리거를 설정하기 전에 반드시 수동으로 한 번 실행해서 코드가 정상 동작하는지 확인합니다.

    1. 상단 함수 선택 드롭다운에서 resetAttendance를 선택합니다.
    2. ▶ 실행 버튼을 클릭합니다.
    3. 처음 실행 시 권한 승인 팝업이 나타납니다. "권한 검토" → 본인 계정 선택 → "허용"을 클릭합니다.
    4. 스프레드시트로 돌아가서 D열이 모두 "미출근"으로 채워졌는지 확인합니다.

    주의사항: 트리거를 설정하기 전에 반드시 수동 실행으로 테스트하세요! 트리거가 실행하는 함수에 오류가 있으면 매번 실패 알림 이메일을 받게 됩니다.

    3단계: 시간 기반 트리거 설정

    이제 이 함수를 매일 아침 자동으로 실행되도록 트리거를 설정합니다.

    1. 스크립트 편집기 왼쪽 메뉴에서 ⏰ 트리거 (시계 아이콘)를 클릭합니다.
    2. 우측 하단의 "+ 트리거 추가" 버튼을 클릭합니다.

    3. 트리거 설정 창에서 다음과 같이 선택합니다:

    4. 실행할 함수 선택: resetAttendance

    5. 실행할 배포 선택: Head
    6. 이벤트 소스 선택: 시간 기반
    7. 시간 기반 트리거 유형 선택: 일 단위 타이머

    8. 시각 선택: 오전 7시~8시

    9. 저장 버튼을 클릭합니다.

    실무 TIP: "오전 7시~8시"로 설정하면 이 시간대 안에서 랜덤한 시점에 실행됩니다. 직원들이 8시 30분에 출근한다면, 넉넉하게 "오전 6시~7시"로 설정하면 출근 전에 확실히 초기화가 완료됩니다.

    설정이 완료되면 트리거 목록에 새로운 트리거가 나타납니다. 이제 매일 아침 여러분이 잠들어 있는 시간에도 출결 시트가 자동으로 초기화됩니다! 🎉

    Step 2: 폼 제출 시 자동 상태 업데이트 (이벤트 기반 트리거)¶

    시나리오: 직원들이 구글 폼으로 출근 체크를 하면, 출결 시트의 해당 직원 상태가 자동으로 "출근"으로 변경됩니다.

    1단계: 구글 폼 만들기

    1. 구글 드라이브에서 새로 만들기 → Google 설문지를 클릭합니다.
    2. 설문지 제목을 출근 체크로 변경합니다.
    3. 첫 번째 질문을 다음과 같이 설정합니다:
    4. 질문: 이름
    5. 유형: 단답형

    6. 필수 토글을 켭니다.

    7. 상단 응답 탭을 클릭합니다.

    8. 스프레드시트에 연결 아이콘(초록색 시트 아이콘)을 클릭합니다.
    9. "기존 스프레드시트 선택" → 앞서 만든 트리거 실습 스프레드시트를 선택합니다.
    10. 새 시트가 자동으로 생성됩니다 (보통 "설문지 응답 1" 이름).

    2단계: 스크립트 작성

    다시 스크립트 편집기로 돌아가서, 기존 코드 아래에 다음 함수를 추가합니다:

    /**
 * 폼 제출 시 출결 현황을 자동 업데이트하는 함수
 * @param {Object} e - 폼 제출 이벤트 객체
 */
function onFormSubmitUpdateAttendance(e) {
  // 1. 폼에서 제출된 응답 가져오기
  var responses = e.namedValues;        // {"이름": ["김철수"], "타임스탬프": ["2025/01/15 오전 8:32:15"]}
  var submittedName = responses['이름'][0].trim();  // 앞뒤 공백 제거
  var timestamp = responses['타임스탬프'][0];

  // 2. 출결현황 시트 가져오기
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName('출결현황');

  // 3. 이름이 일치하는 행 찾기
  var data = sheet.getDataRange().getValues();

  for (var i = 1; i < data.length; i++) {  // 0행은 헤더이므로 1부터
    if (data[i][0] === submittedName) {     // A열(이름)과 비교
      // 4. 해당 행의 출근시간(C열)과 상태(D열) 업데이트
      sheet.getRange(i + 1, 3).setValue(timestamp);  // i+1: 배열은 0부터, 시트는 1부터
      sheet.getRange(i + 1, 4).setValue('출근');

      Logger.log(submittedName + ' 출근 처리 완료: ' + timestamp);
      return;  // 찾았으면 종료
    }
  }

  // 5. 이름을 못 찾은 경우
  Logger.log('⚠️ 등록되지 않은 이름: ' + submittedName);
}

    3단계: 이벤트 기반 트리거 설정

    중요: 이 함수는 e (이벤트 객체)를 매개변수로 받기 때문에 수동 실행으로 테스트할 수 없습니다. 트리거를 먼저 설정한 후, 실제 폼을 제출하여 테스트합니다.

    1. 스크립트 편집기 왼쪽 메뉴에서 ⏰ 트리거를 클릭합니다.
    2. "+ 트리거 추가" 버튼을 클릭합니다.

    3. 다음과 같이 설정합니다:

    4. 실행할 함수 선택: onFormSubmitUpdateAttendance

    5. 실행할 배포 선택: Head
    6. 이벤트 소스 선택: 스프레드시트에서

    7. 이벤트 유형 선택: 폼 제출 시

    8. 저장을 클릭합니다.

    4단계: 테스트

    1. 구글 폼 미리보기를 엽니다 (폼 편집 화면 상단 눈 아이콘).
    2. 이름에 김철수를 입력하고 제출합니다.
    3. 스프레드시트 출결현황 시트를 확인합니다.
    4. 김철수의 C열(출근시간)에 타임스탬프가, D열(상태)에 "출근"이 표시되면 성공입니다! 🎉

    실무 TIP: e.namedValues에서 키 이름은 구글 폼의 질문 텍스트와 정확히 일치해야 합니다. 질문이 "이름"이면 responses['이름'], 질문이 "성함"이면 responses['성함']으로 접근해야 합니다. 한글 앞뒤에 보이지 않는 공백이 들어가는 경우가 있으니, 잘 안 되면 Logger.log(JSON.stringify(e.namedValues))로 실제 키 값을 확인해 보세요.

    Step 3: 매주 월요일 주간 요약 자동 생성 (시간 기반 트리거 응용)¶

    시나리오: 매주 월요일 아침, 지난주 출결 데이터를 자동으로 집계하여 "주간요약" 시트에 기록합니다.

    1단계: 스크립트 작성

    기존 코드 아래에 다음 함수를 추가합니다:

    /**
 * 주간 출결 요약을 자동 생성하는 함수
 * 매주 월요일에 실행되어, 현재 출결현황을 주간요약 시트에 기록합니다.
 */
function createWeeklySummary() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();

  // 1. 출결현황 시트에서 데이터 가져오기
  var attendSheet = ss.getSheetByName('출결현황');
  var data = attendSheet.getDataRange().getValues();

  // 2. 통계 계산
  var totalCount = data.length - 1;  // 헤더 제외
  var presentCount = 0;

  for (var i = 1; i < data.length; i++) {
    if (data[i][3] === '출근') {  // D열(상태)이 '출근'인 경우
      presentCount++;
    }
  }

  var absentCount = totalCount - presentCount;

  // 3. 주간요약 시트에 기록
  var summarySheet = ss.getSheetByName('주간요약');
  var now = new Date().toLocaleString();

  summarySheet.appendRow([now, totalCount, presentCount, absentCount]);

  // 4. 로그 기록
  Logger.log('주간 요약 생성 완료 - 총인원: ' + totalCount + 
             ', 출근: ' + presentCount + 
             ', 미출근: ' + absentCount);
}

    2단계: 수동 테스트

    1. 함수 선택 드롭다운에서 createWeeklySummary를 선택합니다.
    2. ▶ 실행 버튼을 클릭합니다.
    3. 스프레드시트의 주간요약 시트를 확인합니다.
    4. 새로운 행에 작성일시, 총인원, 출근완료, 미출근 숫자가 기록되어 있으면 성공입니다.

    3단계: 주간 트리거 설정

    1. ⏰ 트리거 → "+ 트리거 추가"

    2. 다음과 같이 설정합니다:

    3. 실행할 함수 선택: createWeeklySummary

    4. 실행할 배포 선택: Head
    5. 이벤트 소스 선택: 시간 기반
    6. 시간 기반 트리거 유형 선택: 주 단위 타이머
    7. 요일 선택: 월요일

    8. 시각 선택: 오전 8시~9시

    9. 저장을 클릭합니다.

    이제 매주 월요일 아침, 자동으로 주간 요약이 생성됩니다! 📊

    Step 4: 트리거 확인·삭제·오류 대응하기¶

    트리거를 설정했으면 관리하는 법도 알아야 합니다. 이 단계가 실무에서 가장 중요합니다.

    트리거 목록 확인하기

    1. 스크립트 편집기 왼쪽 메뉴에서 ⏰ 트리거를 클릭합니다.
    2. 현재 프로젝트에 설정된 모든 트리거가 목록으로 표시됩니다.
    3. 각 트리거마다 다음 정보를 확인할 수 있습니다:
    4. 함수 이름: 어떤 함수가 실행되는지
    5. 배포: Head (최신 코드)
    6. 이벤트 소스: 시간 기반 / 스프레드시트 등
    7. 이벤트 유형 및 상세: 실행 주기 또는 이벤트 종류

    실행 로그 확인하기 (오류 찾기)

    1. 스크립트 편집기 왼쪽 메뉴에서 📋 실행 (실행 로그 아이콘)을 클릭합니다.
    2. 모든 실행 기록이 시간순으로 표시됩니다.
    3. 각 실행 기록에서 확인할 수 있는 정보:
    4. 실행 상태: ✅ 완료 / ❌ 실패
    5. 실행 시간: 언제 실행되었는지
    6. 트리거 유형: 어떤 트리거에 의해 실행되었는지
    7. 오류 메시지: 실패 시 구체적인 에러 내용

    실무 TIP: 트리거 실행이 실패하면 구글이 해당 Google 계정의 이메일로 오류 알림을 보내줍니다. 이메일 제목은 보통 "Google Apps Script에서 프로젝트 [이름]의 함수 [함수명] 실행에 실패했습니다" 형태입니다. 이 이메일을 무시하지 마세요!

    트리거 삭제하기

    1. 트리거 목록에서 삭제할 트리거 우측의 ⋮ (점 세 개) 메뉴를 클릭합니다.
    2. "트리거 삭제"를 선택합니다.

    주의사항: 트리거는 수정이 불가능합니다. 시간을 변경하고 싶다면 기존 트리거를 삭제하고 새로 만들어야 합니다.

    📝 전체 코드¶

    아래는 이번 장에서 작성한 모든 코드를 하나로 모은 것입니다. 복사해서 바로 사용할 수 있습니다.

    // ============================================
// Chapter 05: 트리거 실습 - 전체 코드
// ============================================

/**
 * [시간 기반 트리거용] 매일 아침 출결 현황을 초기화하는 함수
 * 
 * 트리거 설정: 시간 기반 → 일 단위 타이머 → 오전 7시~8시
 */
function resetAttendance() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName('출결현황');

  var lastRow = sheet.getLastRow();

  if (lastRow < 2) {
    Logger.log('초기화할 데이터가 없습니다.');
    return;
  }

  // 출근시간(C열) 비우기
  var timeRange = sheet.getRange(2, 3, lastRow - 1, 1);
  timeRange.clearContent();

  // 상태(D열)를 "미출근"으로 설정
  var statusRange = sheet.getRange(2, 4, lastRow - 1, 1);
  var statusValues = [];
  for (var i = 0; i < lastRow - 1; i++) {
    statusValues.push(['미출근']);
  }
  statusRange.setValues(statusValues);

  Logger.log('출결 현황 초기화 완료: ' + new Date().toLocaleString());
}


/**
 * [이벤트 기반 트리거용] 폼 제출 시 출결 상태를 자동 업데이트하는 함수
 * 
 * 트리거 설정: 스프레드시트에서 → 폼 제출 시
 * 
 * @param {Object} e - 폼 제출 이벤트 객체
 */
function onFormSubmitUpdateAttendance(e) {
  var responses = e.namedValues;
  var submittedName = responses['이름'][0].trim();
  var timestamp = responses['타임스탬프'][0];

  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName('출결현황');
  var data = sheet.getDataRange().getValues();

  for (var i = 1; i < data.length; i++) {
    if (data[i][0] === submittedName) {
      sheet.getRange(i + 1, 3).setValue(timestamp);
      sheet.getRange(i + 1, 4).setValue('출근');
      Logger.log(submittedName + ' 출근 처리 완료: ' + timestamp);
      return;
    }
  }

  Logger.log('⚠️ 등록되지 않은 이름: ' + submittedName);
}


/**
 * [시간 기반 트리거용] 매주 월요일 주간 출결 요약을 자동 생성하는 함수
 * 
 * 트리거 설정: 시간 기반 → 주 단위 타이머 → 월요일 → 오전 8시~9시
 */
function createWeeklySummary() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();

  var attendSheet = ss.getSheetByName('출결현황');
  var data = attendSheet.getDataRange().getValues();

  var totalCount = data.length - 1;
  var presentCount = 0;

  for (var i = 1; i < data.length; i++) {
    if (data[i][3] === '출근') {
      presentCount++;
    }
  }

  var absentCount = totalCount - presentCount;

  var summarySheet = ss.getSheetByName('주간요약');
  var now = new Date().toLocaleString();

  summarySheet.appendRow([now, totalCount, presentCount, absentCount]);

  Logger.log('주간 요약 생성 완료 - 총인원: ' + totalCount + 
             ', 출근: ' + presentCount + 
             ', 미출근: ' + absentCount);
}

    ⚠️ 자주 하는 실수¶

    실수 1: 같은 트리거를 여러 번 생성하기 🔄¶

    증상: 함수가 한 번 실행될 때마다 2번, 3번 중복 실행됩니다. 이메일이 2통씩 발송되거나, 데이터가 2줄씩 입력됩니다.

    원인: "트리거 추가" 버튼을 여러 번 클릭하여 동일한 트리거가 중복 생성된 경우입니다. 앱스 스크립트는 같은 함수에 대해 동일한 트리거를 여러 개 만드는 것을 막지 않습니다.

    해결 방법: 1. ⏰ 트리거 메뉴에서 트리거 목록을 확인합니다. 2. 같은 함수에 대한 중복 트리거를 찾아 삭제합니다. 3. 필요한 트리거 하나만 남깁니다.

    예방법: 트리거를 새로 만들기 전에 항상 기존 트리거 목록을 먼저 확인하는 습관을 들이세요.

    실수 2: 이벤트 객체(e) 관련 오류 무시하기 🚫¶

    증상: 폼 제출 트리거 함수를 수동으로 실행(▶ 버튼)했더니 TypeError: Cannot read properties of undefined 오류가 발생합니다.

    원인: onFormSubmitUpdateAttendance(e) 같은 이벤트 기반 함수는 트리거가 자동으로 실행할 때만 e 객체가 전달됩니다. 수동 실행 시에는 e가 undefined이므로 e.namedValues에 접근할 수 없습니다.

    해결 방법: 이벤트 기반 함수는 수동 실행으로 테스트하지 마세요. 반드시 실제 이벤트(폼 제출 등)를 발생시켜서 테스트해야 합니다. 디버깅이 필요한 경우, 다음과 같이 임시 테스트 코드를 사용하세요:

    // 테스트용 함수 (디버깅 후 삭제)
function testFormSubmit() {
  var fakeEvent = {
    namedValues: {
      '이름': ['김철수'],
      '타임스탬프': ['2025/01/15 오전 8:32:15']
    }
  };
  onFormSubmitUpdateAttendance(fakeEvent);
}

    실수 3: 트리거 오류 이메일을 무시하기 📧¶

    증상: 구글에서 "스크립트 실행 실패" 이메일이 매일 오지만 무시합니다. 어느 날 보니 스크립트가 한 달째 작동하지 않고 있었습니다.

    원인: 트리거 실행 중 오류가 계속 발생하면 구글이 트리거를 자동으로 비활성화할 수 있습니다. 또한 오류가 반복되면 다른 트리거의 할당량에도 영향을 미칩니다.

    해결 방법: 1. 오류 이메일을 받으면 즉시 스크립트 편집기의 📋 실행 메뉴에서 오류 내용을 확인합니다. 2. 코드를 수정합니다. 3. 수동 실행으로 테스트합니다. 4. 필요하면 기존 트리거를 삭제하고 새로 생성합니다.

    예방법: 매주 한 번 트리거 상태 점검 시간을 달력에 넣어두세요. 5분이면 충분합니다.

    실수 4: 시트 이름을 변경한 후 코드를 업데이트하지 않기 📛¶

    증상: 잘 되던 스크립트가 갑자기 오류가 납니다. "시트를 찾을 수 없습니다" 같은 에러 메시지가 뜹니다.

    원인: 코드에서 getSheetByName('출결현황')으로 시트를 찾는데, 누군가 시트 이름을 "출결 현황"(띄어쓰기 추가)이나 "출결현황_2025"로 변경한 경우입니다.

    해결 방법: 시트 이름을 변경했다면, 스크립트에서도 해당 이름을 동일하게 수정해야 합니다. 시트 이름은 띄어쓰기, 대소문자까지 정확히 일치해야 합니다.

    예방법: 자동화가 걸려 있는 시트에는 이름 앞에 [자동] 같은 표시를 달아서 함부로 변경하지 않도록 알려두세요. 예: [자동]출결현황

    도전 1: 정확한 시각에 실행하기 (중급) ⏰¶

    앞서 시간 기반 트리거는 "1시간 범위" 안에서 실행된다고 했습니다. 정확히 특정 시각에 실행하고 싶다면 다음 방법을 사용합니다:

    /**
 * 1분마다 실행되는 트리거에 연결하여
 * 정확히 오전 9시 0분에만 동작하게 하는 함수
 */
function preciseTrigger() {
  var now = new Date();
  var hour = now.getHours();
  var minute = now.getMinutes();

  // 오전 9시 0분일 때만 실행
  if (hour === 9 && minute === 0) {
    // 여기에 실행할 코드를 넣습니다
    Logger.log('정확히 9시에 실행됨!');

    // 예: resetAttendance(); 를 호출
  }
}

    이 함수에 1분 단위 시간 기반 트리거를 걸면, 매 분마다 현재 시각을 확인하고 9시 0분일 때만 실제 작업을 수행합니다.

    주의사항: 1분 간격 트리거는 할당량을 빠르게 소진합니다. 꼭 필요한 경우에만 사용하세요. 대부분의 업무에서는 1시간 범위 실행으로도 충분합니다.

    도전 2: 코드로 트리거 생성하기 (고급) 💻¶

    편집기 UI가 아닌, 코드로 직접 트리거를 생성할 수도 있습니다. 이 방법은 다수의 트리거를 자동으로 관리할 때 유용합니다.

    /**
 * 코드로 시간 기반 트리거를 생성하는 함수
 * 이 함수는 한 번만 수동 실행합니다.
 */
function createTriggerByCode() {
  // 기존에 같은 함수의 트리거가 있으면 먼저 삭제
  var triggers = ScriptApp.getProjectTriggers();
  for (var i = 0; i < triggers.length; i++) {
    if (triggers[i].getHandlerFunction() === 'resetAttendance') {
      ScriptApp.deleteTrigger(triggers[i]);
    }
  }

  // 새 트리거 생성: 매일 오전 7시에 resetAttendance 실행
  ScriptApp.newTrigger('resetAttendance')
    .timeBased()
    .everyDays(1)
    .atHour(7)
    .create();

  Logger.log('트리거가 코드로 생성되었습니다!');
}

    실무 TIP: 코드로 트리거를 관리하면 "기존 트리거 삭제 → 새 트리거 생성"을 자동화할 수 있어서, 중복 트리거 문제를 원천적으로 예방할 수 있습니다. 실무 프로젝트가 복잡해질수록 이 방법을 추천합니다.

    시나리오 A – 마감일 알림 - 스프레드시트에 프로젝트 목록과 마감일을 관리합니다 - 매일 아침 트리거로 오늘이 마감일인 프로젝트를 찾습니다 - 해당 프로젝트가 있으면 로그에 기록합니다 (이메일 발송은 이후 챕터에서 다룹니다)

    시나리오 B – 만족도 조사 실시간 집계 - 구글 폼으로 만족도 조사를 받습니다 (1~5점 척도) - 폼 제출 트리거로 응답이 올 때마다 평균 점수를 자동 계산합니다 - 별도 "집계" 시트에 현재 응답 수와 평균 점수를 업데이트합니다

    여기까지가 Part 1: 앱스 스크립트 첫걸음입니다. 지금까지 배운 것을 정리하면:

    • Chapter 01~02: 앱스 스크립트가 무엇이고, 어디서 코드를 작성하는지
    • Chapter 03~04: 스프레드시트를 읽고 쓰는 기본 코드 작성법
    • Chapter 05 (이번 장): 코드를 자동으로 실행시키는 트리거 설정

    이 세 가지 – 코드 작성 환경 + 데이터 처리 + 자동 실행 – 이 앱스 스크립트 자동화의 3대 기둥입니다.

    다음 장부터는 Part 2로 넘어갑니다. 실제 업무에서 가장 많이 쓰이는 자동화 패턴들을 본격적으로 구현합니다. 이메일 자동 발송, 데이터 정리, 다양한 구글 서비스 연동 등 실전 프로젝트가 기다리고 있습니다.
