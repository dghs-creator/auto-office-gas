    오류 해결과 디버깅 – 코드가 안 될 때 대처법¶

    Part 6: [2권] 통합 활용과 확장 – 나만의 자동화 시스템 만들기 | 22차시

    🎯 이 장에서 배우는 것¶

    • GAS에서 자주 발생하는 오류 5가지 유형을 보고 즉시 원인을 파악할 수 있다
    • Logger.log와 실행 로그(Execution log)를 활용해 문제 지점을 추적할 수 있다
    • try-catch 구문으로 오류 발생 시 프로그램이 멈추지 않도록 안전장치를 만들 수 있다
    • 오류 발생 시 자동으로 이메일 알림을 보내는 모니터링 코드를 작성할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분이 지금까지 21차시에 걸쳐 만든 자동화 코드들, 잘 돌아가고 있나요?

    솔직히 말씀드리면, 코드는 반드시 깨집니다. 누군가 시트 이름을 바꾸고, 데이터 형식이 달라지고, API 서버가 잠깐 멈추고, 권한이 변경됩니다. 문제는 오류가 "발생하느냐 아니냐"가 아니라, "발생했을 때 얼마나 빨리 원인을 찾고 고치느냐"입니다.

    🏥 비유: 디버깅은 '코드의 건강검진'입니다. 의사가 환자의 증상을 듣고, 검사를 하고, 원인을 찾아 치료하듯이 — 우리도 오류 메시지를 읽고, 로그를 확인하고, 원인을 찾아 수정합니다. 이 장을 마치면 여러분은 "코드 주치의"가 됩니다.

    현실 시나리오를 하나 보겠습니다.

    월요일 아침, 매주 자동 발송되던 주간 보고 이메일이 오지 않습니다. 스프레드시트를 열어보니 아무 변화가 없습니다. GAS 편집기를 열어보니 실행 기록에 빨간 글씨가 가득합니다. 이때 여러분은 두 가지 중 하나를 합니다.

    • ❌ 패닉 → 코드 전체 삭제 → 처음부터 다시 만들기 (2시간 소요)
    • ✅ 오류 메시지 읽기 → 원인 파악 → 한 줄 수정 (5분 소요)

    이 장은 여러분을 ✅ 쪽 사람으로 만드는 시간입니다.

    📚 핵심 개념¶

    개념 1: GAS 오류 메시지 읽는 법 — 빨간 글씨는 힌트다 🔍¶

    1) 비유로 시작

    자동차 계기판의 경고등을 생각해보세요. 엔진 경고등이 켜지면 "차가 고장났다!"고 패닉하기보다, 어떤 경고등인지를 먼저 확인하죠? 엔진오일 부족인지, 타이어 공기압 부족인지에 따라 대처가 완전히 다릅니다. GAS의 오류 메시지도 똑같습니다. 빨간 글씨는 "어디가 왜 아픈지" 알려주는 진단서입니다.

    2) 정확한 정의

    GAS 오류 메시지는 세 가지 정보를 담고 있습니다.

    • 오류 유형(Error Type): 어떤 종류의 문제인지 (TypeError, ReferenceError 등)
    • 오류 내용(Message): 구체적으로 무엇이 잘못됐는지
    • 발생 위치(Line Number): 코드 몇 번째 줄에서 문제가 생겼는지

    3) 예시로 확인

    TypeError: Cannot read properties of null (reading 'getRange')
at myFunction (Code:5:18)

    이 메시지를 해부해보겠습니다.

    • TypeError → 데이터 타입 관련 문제
    • Cannot read properties of null → 어떤 값이 null(비어있음)인데, 그 안에서 뭔가를 읽으려 했다
    • reading 'getRange' → getRange를 호출하려 했다
    • Code:5:18 → Code.gs 파일의 5번째 줄, 18번째 글자 위치

    번역하면: "5번째 줄에서 getRange를 호출했는데, 그 앞의 객체가 null입니다." → 높은 확률로 시트 이름이 틀렸거나 시트가 없는 것입니다.

    실무 TIP: 오류 메시지의 영어가 어렵다면, 메시지 전체를 복사해서 ChatGPT에 붙여넣고 "이 오류 한국어로 설명해줘"라고 물어보세요. 지금까지 배운 AI 활용법이 여기서도 빛을 발합니다!

    flowchart LR A["🔴 오류 발생"] --> B["오류 메시지 읽기"] B --> C{"무슨 유형?"} C --> D["TypeError\n타입 문제"] C --> E["ReferenceError\n이름 문제"] C --> F["Exception\nGAS 고유 오류"] D --> G["원인 파악 & 수정"] E --> G F --> G

    핵심 포인트: 오류 메시지는 적이 아니라 아군입니다. "오류 유형 → 구체 내용 → 줄 번호" 세 가지만 읽으면 원인의 80%를 파악할 수 있습니다.

    개념 2: 5대 빈출 오류와 해결법 — 이것만 알면 90%는 해결 🛠️¶

    1) 비유로 시작

    병원 응급실에도 '가장 많이 오는 증상 Top 5'가 있듯이, GAS에도 반복적으로 발생하는 오류 패턴이 있습니다. 이 다섯 가지만 외워두면 실무에서 마주하는 오류 대부분을 해결할 수 있습니다.

    2) 5대 빈출 오류 정리

    🔴 오류 1: 시트 이름 오타 / 시트 없음

    • 메시지: TypeError: Cannot read properties of null (reading 'getRange')
    • 원인: getSheetByName("매출현황")에서 시트 이름이 실제와 다름
    • 흔한 상황: 누군가 시트 탭 이름을 "매출현황" → "매출_현황"으로 변경, 앞뒤 공백이 들어감
    • 해결법: 스프레드시트에서 시트 탭 이름을 정확히 복사해서 코드에 붙여넣기
    // ❌ 이렇게 하면 오류 발생 가능
var sheet = ss.getSheetByName("매출현황");
sheet.getRange("A1").setValue("테스트"); // sheet가 null이면 여기서 터짐

// ✅ 안전한 방법: 시트 존재 여부를 먼저 확인
var sheet = ss.getSheetByName("매출현황");
if (sheet === null) {
  Logger.log("⚠️ '매출현황' 시트를 찾을 수 없습니다. 이름을 확인하세요.");
  return; // 함수 종료
}
sheet.getRange("A1").setValue("테스트");

    🔴 오류 2: 범위 지정 오류

    • 메시지: Exception: The parameters (number, number) don't match the method signature for SpreadsheetApp.Sheet.getRange
    • 원인: getRange에 잘못된 인자를 넘김 (행/열 번호가 0이거나 음수)
    • 흔한 상황: 빈 시트에서 getLastRow()가 0을 반환하고, 이걸 그대로 getRange에 넣음
    • 해결법: getLastRow() 결과가 0인 경우를 별도로 처리
    // ❌ 빈 시트에서 오류 발생
var lastRow = sheet.getLastRow(); // 빈 시트면 0 반환
var data = sheet.getRange(1, 1, lastRow, 3).getValues(); // lastRow가 0이면 오류!

// ✅ 안전한 방법
var lastRow = sheet.getLastRow();
if (lastRow === 0) {
  Logger.log("시트에 데이터가 없습니다.");
  return;
}
var data = sheet.getRange(1, 1, lastRow, 3).getValues();

    🔴 오류 3: 권한 문제

    • 메시지: Exception: You do not have permission to call SpreadsheetApp.openById
    • 원인: 다른 사람의 스프레드시트에 접근 권한이 없음, 또는 첫 실행 시 권한 승인을 하지 않음
    • 흔한 상황: 동료가 공유한 시트 ID로 코드를 만들었는데, 해당 시트의 편집 권한이 없음
    • 해결법:
    • 첫 실행 시 나타나는 "권한 검토" 대화상자에서 반드시 "허용" 클릭
    • 다른 파일을 열 때는 해당 파일에 대한 편집 권한이 있는지 먼저 확인
    • Google Workspace 관리자가 외부 앱을 차단한 경우 IT팀에 문의

    🔴 오류 4: API 한도 초과

    • 메시지: Exception: Service invoked too many times for one day: email 또는 Quota exceeded
    • 원인: GAS의 일일 사용 한도를 초과함
    • 흔한 상황: 반복문 안에서 이메일을 수백 통 보내려고 시도
    • 주요 한도 (무료 계정 기준):
    • 이메일 발송: 하루 100통
    • 스크립트 실행 시간: 1회 최대 6분
    • URL 요청(UrlFetch): 하루 20,000회
    • 트리거 실행: 하루 최대 90분
    • 해결법: 대량 작업은 나눠서 처리, 불필요한 API 호출 줄이기
    // ❌ 반복문 안에서 매번 시트 열기 (느리고 한도 소모)
for (var i = 0; i < 100; i++) {
  var ss = SpreadsheetApp.openById("시트ID"); // 매번 열기!
  var sheet = ss.getSheetByName("Data");
  sheet.getRange(i + 1, 1).setValue(i);
}

// ✅ 시트는 한 번만 열고, 데이터는 모아서 한 번에 쓰기
var ss = SpreadsheetApp.openById("시트ID");
var sheet = ss.getSheetByName("Data");
var data = [];
for (var i = 0; i < 100; i++) {
  data.push([i]);
}
sheet.getRange(1, 1, data.length, 1).setValues(data); // 한 번에 쓰기!

    🔴 오류 5: 데이터 타입 불일치

    • 메시지: TypeError: Cannot read properties of undefined 또는 예상과 다른 결과
    • 원인: 숫자를 기대했는데 문자가 들어옴, 날짜 형식이 다름, 빈 셀이 예상과 다른 값을 반환
    • 흔한 상황: 셀에 "1,000"(쉼표 포함 문자열)이 있는데 숫자로 계산하려 함
    • 해결법: typeof로 타입을 확인하고, 필요시 명시적으로 변환
    // ❌ 데이터 타입을 확인하지 않고 바로 계산
var price = sheet.getRange("B2").getValue(); // "1,000" (문자열)
var total = price * 10; // NaN 발생!

// ✅ 타입 확인 후 변환
var price = sheet.getRange("B2").getValue();
Logger.log("price의 타입: " + typeof price + ", 값: " + price);
if (typeof price === "string") {
  price = Number(price.replace(/,/g, "")); // 쉼표 제거 후 숫자 변환
}
var total = price * 10; // 10000 정상 계산

    개념 3: Logger.log와 실행 로그 — 코드의 속마음을 들여다보기 🔬¶

    1) 비유로 시작

    요리를 하다가 맛이 이상하면 어떻게 하시나요? 중간중간 맛을 봅니다. "소금을 넣은 후" 맛보기, "간장을 넣은 후" 맛보기… 이렇게 하면 어느 시점에서 맛이 틀어졌는지 알 수 있죠. Logger.log()는 코드의 중간 맛보기입니다. 각 단계에서 변수에 무슨 값이 들어있는지 확인할 수 있습니다.

    2) 정확한 정의

    • Logger.log(): 코드 실행 중에 메시지나 변수 값을 기록하는 함수. 실행이 끝나면 로그 창에서 확인할 수 있습니다.
    • console.log(): Logger.log와 같은 역할. 최신 GAS에서는 둘 다 사용 가능하며, console.log는 실행 로그(Execution log)에 자동으로 표시됩니다.
    • 실행 로그(Execution log): GAS 편집기 하단에 나타나는 패널. 코드 실행 결과와 로그 메시지가 시간순으로 표시됩니다.

    3) 예시로 확인: 로그로 문제 추적하기

    아래 코드는 시트에서 데이터를 읽어 이메일을 보내는 함수입니다. 어딘가에 버그가 있다고 가정하고, Logger.log를 단계별로 넣어보겠습니다.

    핵심 포인트: Logger.log는 코드의 X-ray입니다. "여기까지는 정상 → 여기서 문제"의 경계선을 찾으면 오류 원인의 90%가 해결됩니다. 의심스러운 곳에 아낌없이 넣으세요.

    개념 4: try-catch — 오류가 나도 멈추지 않는 안전장치 🛡️¶

    1) 비유로 시작

    고속도로를 달리다가 앞에 돌멩이가 있으면? 차가 튕겨져 사고가 납니다. 하지만 범퍼(완충장치)가 있으면 충격을 흡수하고 안전하게 멈출 수 있죠. try-catch는 코드의 범퍼입니다. "이 구간에서 오류가 날 수 있어. 오류가 나면 이렇게 처리해"라고 미리 지정해두는 것입니다.

    2) 정확한 정의

    try {
  // 오류가 발생할 수 있는 코드
} catch (error) {
  // 오류가 발생했을 때 실행할 코드
  // error 객체에 오류 정보가 담겨 있음
} finally {
  // (선택) 오류 발생 여부와 관계없이 항상 실행할 코드
}
    • try 블록: "시도해봐" — 정상적으로 실행하고 싶은 코드를 넣습니다
    • catch 블록: "문제가 생기면 이렇게 해" — 오류 발생 시 대체 동작을 정의합니다
    • error 객체: 오류에 대한 정보를 담고 있음. error.message로 오류 메시지 확인, error.stack으로 발생 위치 확인
    • finally 블록: (선택사항) 오류가 나든 안 나든 무조건 실행. 정리 작업에 사용

    3) 예시로 확인

    try-catch 없이 (위험한 코드):

    function processAllSheets() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheetNames = ["1월", "2월", "3월", "4월"];

  for (var i = 0; i < sheetNames.length; i++) {
    var sheet = ss.getSheetByName(sheetNames[i]);
    var total = sheet.getRange("B10").getValue(); // "3월" 시트가 없으면 여기서 멈춤!
    Logger.log(sheetNames[i] + " 합계: " + total);
  }
  // "3월" 시트가 없으면 → 4월도 처리 못하고 전체 중단!
}

    try-catch 적용 (안전한 코드):

    function processAllSheetsSafe() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheetNames = ["1월", "2월", "3월", "4월"];
  var errors = []; // 오류 모아두기

  for (var i = 0; i < sheetNames.length; i++) {
    try {
      var sheet = ss.getSheetByName(sheetNames[i]);
      if (!sheet) {
        throw new Error(sheetNames[i] + " 시트를 찾을 수 없습니다");
      }
      var total = sheet.getRange("B10").getValue();
      Logger.log("✅ " + sheetNames[i] + " 합계: " + total);
    } catch (error) {
      Logger.log("❌ " + sheetNames[i] + " 처리 실패: " + error.message);
      errors.push(sheetNames[i] + ": " + error.message);
      // 멈추지 않고 다음 시트로 계속 진행!
    }
  }

  // 오류 요약 보고
  if (errors.length > 0) {
    Logger.log("===== 오류 요약 =====");
    Logger.log("총 " + errors.length + "건의 오류 발생:");
    errors.forEach(function(err) { Logger.log("  - " + err); });
  } else {
    Logger.log("✅ 모든 시트 처리 완료!");
  }
}

    결과: "3월" 시트가 없어도 → 로그에 오류 기록 → "4월"까지 정상 처리 → 마지막에 오류 요약 출력

    flowchart TD A["try 블록 실행"] --> B{"오류 발생?"} B -- "No" --> C["정상 진행"] B -- "Yes" --> D["catch 블록 실행\n오류 정보 확인"] C --> E["finally 블록\n항상 실행"] D --> E E --> F["다음 코드 계속 실행\n프로그램 멈추지 않음!"]

    throw로 의도적 오류 만들기:

    throw는 "이 상황은 오류로 처리하겠다"고 직접 선언하는 것입니다.

    function validateData(value) {
  if (value === "" || value === null || value === undefined) {
    throw new Error("필수 값이 비어있습니다");
  }
  if (typeof value !== "number") {
    throw new Error("숫자만 입력 가능합니다. 현재 타입: " + typeof value);
  }
  if (value < 0) {
    throw new Error("음수는 허용되지 않습니다. 현재 값: " + value);
  }
  return value;
}

    주의사항: try-catch를 남용하지 마세요! 모든 코드를 try-catch로 감싸면 정작 중요한 오류를 놓칠 수 있습니다. "오류가 날 수 있는 특정 구간"에만 적용하세요. 외부 API 호출, 파일 접근, 사용자 입력 처리 등이 좋은 대상입니다.

    핵심 포인트: try-catch는 "오류를 없애는 것"이 아니라 "오류가 나도 프로그램이 안전하게 계속 돌아가게 하는 것"입니다. catch 안에서 반드시 오류를 기록(로그, 이메일 등)하세요.

    Step 3: try-catch로 오류 처리 추가하기 🛡️¶

    이제 각 행 처리를 try-catch로 감싸서, 한 행에서 오류가 나도 나머지 행을 계속 처리하도록 만듭니다.

    /**
 * Step 3: try-catch로 안전하게 처리하는 함수
 */
function processSalesData() {
  Logger.log("===== processSalesData 시작 =====");

  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sheet = ss.getSheetByName("매출데이터");

  if (!sheet) {
    Logger.log("❌ '매출데이터' 시트를 찾을 수 없습니다.");
    return;
  }

  var lastRow = sheet.getLastRow();
  if (lastRow < 2) {
    Logger.log("❌ 처리할 데이터가 없습니다.");
    return;
  }

  var data = sheet.getRange(2, 1, lastRow - 1, 4).getValues();

  var successCount = 0;
  var errorCount = 0;
  var errorDetails = [];
  var totalSales = 0;

  for (var i = 0; i < data.length; i++) {
    var rowNum = i + 2;

    try {
      var date = data[i][0];
      var name = data[i][1];
      var sales = data[i][2];
      var email = data[i][3];

      // 유효성 검사: 빈 행 건너뛰기
      if (!date && !name && !sales && !email) {
        Logger.log(rowNum + "행: 빈 행 - 건너뜀");
        continue; // 다음 반복으로
      }

      // 유효성 검사: 필수 값 확인
      if (!name) {
        throw new Error("담당자 이름이 비어있습니다");
      }

      // 유효성 검사: 매출액 타입 확인
      if (typeof sales !== "number") {
        throw new Error("매출액이 숫자가 아닙니다 (현재 값: " + sales + ")");
      }

      // 유효성 검사: 매출액 범위 확인
      if (sales < 0) {
        throw new Error("매출액이 음수입니다 (현재 값: " + sales + ")");
      }

      // 모든 검사 통과 - 정상 처리
      totalSales += sales;
      successCount++;
      Logger.log("✅ " + rowNum + "행: " + name + " - " + sales.toLocaleString() + "원 처리 완료");

    } catch (error) {
      errorCount++;
      var errorMsg = rowNum + "행 (" + (data[i][1] || "이름없음") + "): " + error.message;
      errorDetails.push(errorMsg);
      Logger.log("❌ " + errorMsg);
      // 오류가 나도 멈추지 않고 다음 행으로 계속!
    }
  }

  // 처리 결과 요약
  Logger.log("===== 처리 결과 요약 =====");
  Logger.log("성공: " + successCount + "건");
  Logger.log("오류: " + errorCount + "건");
  Logger.log("총 매출: " + totalSales.toLocaleString() + "원");

  if (errorDetails.length > 0) {
    Logger.log("--- 오류 상세 ---");
    errorDetails.forEach(function(detail) {
      Logger.log("  " + detail);
    });
  }

  Logger.log("===== processSalesData 종료 =====");

  // 다음 Step에서 사용할 수 있도록 결과 반환
  return {
    success: successCount,
    errors: errorCount,
    totalSales: totalSales,
    errorDetails: errorDetails
  };
}

    Step 4: 오류 발생 시 이메일 알림 보내기 📧¶

    트리거로 자동 실행되는 코드에서 오류가 나면, 여러분이 GAS를 열어보기 전까지는 알 수 없습니다. 오류 발생 시 자동으로 이메일을 보내는 알림 시스템을 추가합니다.

    /**
 * Step 4: 오류 알림 이메일을 보내는 함수
 */
function sendErrorAlert(functionName, errorDetails) {
  var adminEmail = Session.getActiveUser().getEmail(); // 본인 이메일
  var now = Utilities.formatDate(new Date(), "Asia/Seoul", "yyyy-MM-dd HH:mm:ss");

  var subject = "⚠️ [GAS 오류 알림] " + functionName + " 실행 중 오류 발생";

  var body = "안녕하세요,\n\n"
    + "GAS 자동화 스크립트에서 오류가 발생했습니다.\n\n"
    + "📌 함수명: " + functionName + "\n"
    + "📌 발생 시간: " + now + "\n"
    + "📌 오류 건수: " + errorDetails.length + "건\n\n"
    + "--- 오류 상세 ---\n";

  errorDetails.forEach(function(detail, index) {
    body += (index + 1) + ". " + detail + "\n";
  });

  body += "\n---\n"
    + "GAS 편집기에서 실행 로그를 확인해주세요.\n"
    + "이 메일은 자동 발송되었습니다.";

  try {
    MailApp.sendEmail(adminEmail, subject, body);
    Logger.log("📧 오류 알림 이메일 발송 완료: " + adminEmail);
  } catch (mailError) {
    Logger.log("📧 이메일 발송 실패: " + mailError.message);
  }
}

    Step 5: 모든 것을 하나로 합치기 — 완성된 안전한 자동화 🎯¶

    Step 2~4를 통합하여, 실무에서 바로 사용할 수 있는 완성형 코드를 만듭니다.

    /**
 * Step 5: 완성된 안전한 매출 데이터 처리 함수
 * - 데이터 유효성 검사
 * - 오류 발생 시에도 계속 처리
 * - 처리 결과를 시트에 기록
 * - 오류 발생 시 이메일 알림
 */
function processSalesDataSafe() {
  Logger.log("===== processSalesDataSafe 시작 =====");

  var functionName = "processSalesDataSafe";
  var resultSheet;

  try {
    // ========== 1. 시트 준비 ==========
    var ss = SpreadsheetApp.getActiveSpreadsheet();
    var sheet = ss.getSheetByName("매출데이터");

    if (!sheet) {
      throw new Error("'매출데이터' 시트를 찾을 수 없습니다. 시트 이름을 확인하세요.");
    }

    // 결과 기록용 시트 (없으면 생성)
    resultSheet = ss.getSheetByName("처리결과");
    if (!resultSheet) {
      resultSheet = ss.insertSheet("처리결과");
      resultSheet.getRange("A1:D1").setValues([["처리시간", "상태", "성공건수", "오류내용"]]);
      resultSheet.getRange("A1:D1").setFontWeight("bold");
      Logger.log("'처리결과' 시트 생성 완료");
    }

    // ========== 2. 데이터 읽기 ==========
    var lastRow = sheet.getLastRow();
    if (lastRow < 2) {
      Logger.log("처리할 데이터가 없습니다.");
      return;
    }

    var data = sheet.getRange(2, 1, lastRow - 1, 4).getValues();
    Logger.log("총 " + data.length + "행 데이터 읽기 완료");

    // ========== 3. 데이터 처리 (try-catch 적용) ==========
    var successCount = 0;
    var errorCount = 0;
    var errorDetails = [];
    var totalSales = 0;

    for (var i = 0; i < data.length; i++) {
      var rowNum = i + 2;

      try {
        var date = data[i][0];
        var name = data[i][1];
        var sales = data[i][2];
        var email = data[i][3];

        // 빈 행 건너뛰기
        if (!date && !name && !sales && !email) {
          continue;
        }

        // 필수 값 검사
        if (!name) throw new Error("담당자 이름 누락");
        if (!date) throw new Error("날짜 누락");

        // 매출액 검사
        if (typeof sales === "string") {
          // 쉼표가 포함된 숫자 문자열 처리 시도
          var cleaned = Number(sales.toString().replace(/,/g, ""));
          if (isNaN(cleaned)) {
            throw new Error("매출액이 숫자가 아닙니다: '" + sales + "'");
          }
          sales = cleaned;
        }

        if (typeof sales !== "number" || isNaN(sales)) {
          throw new Error("매출액을 숫자로 변환할 수 없습니다: " + sales);
        }

        if (sales < 0) {
          throw new Error("매출액이 음수입니다: " + sales);
        }

        // 정상 처리
        totalSales += sales;
        successCount++;
        Logger.log("✅ " + rowNum + "행 처리 완료: " + name + " / " + sales + "원");

      } catch (rowError) {
        errorCount++;
        var msg = rowNum + "행(" + (data[i][1] || "이름없음") + "): " + rowError.message;
        errorDetails.push(msg);
        Logger.log("❌ " + msg);
      }
    }

    // ========== 4. 결과 기록 ==========
    var now = Utilities.formatDate(new Date(), "Asia/Seoul", "yyyy-MM-dd HH:mm:ss");
    var resultRow = resultSheet.getLastRow() + 1;
    var statusText = errorCount === 0 ? "✅ 전체 성공" : "⚠️ 일부 오류";
    var errorText = errorDetails.length > 0 ? errorDetails.join("\n") : "없음";

    resultSheet.getRange(resultRow, 1, 1, 4).setValues([
      [now, statusText + " (성공:" + successCount + "/오류:" + errorCount + ")", successCount, errorText]
    ]);

    Logger.log("처리 결과를 '처리결과' 시트에 기록했습니다.");

    // ========== 5. 오류 알림 ==========
    if (errorDetails.length > 0) {
      sendErrorAlert(functionName, errorDetails);
    }

    // ========== 6. 최종 요약 ==========
    Logger.log("===== 최종 요약 =====");
    Logger.log("성공: " + successCount + "건 / 오류: " + errorCount + "건");
    Logger.log("총 매출: " + totalSales.toLocaleString() + "원");

  } catch (fatalError) {
    // 전체 프로세스 수준의 치명적 오류
    Logger.log("🔴 치명적 오류 발생: " + fatalError.message);
    Logger.log("스택: " + fatalError.stack);

    try {
      sendErrorAlert(functionName, ["치명적 오류: " + fatalError.message]);
    } catch (e) {
      Logger.log("알림 이메일 발송도 실패: " + e.message);
    }
  }

  Logger.log("===== processSalesDataSafe 종료 =====");
}

    4. 실행할 함수: processSalesDataSafe
    5. 이벤트 소스: 시간 기반
    6. 트리거 유형: 매일 타이머 (또는 매주)

    8. 저장 클릭
